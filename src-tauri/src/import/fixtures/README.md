# 匯入回歸夾具：乾淨替代測試卡

`clean_cards_tests.rs` 用。兩張卡照成人原卡的**結構**重做（條目中繼資料逐條照抄，只換標題、關鍵字、內文，題材換成邊境要塞／冒險者公會），內文沿用原卡的簡體中文。

- `clean-orc-cave.json`：「灰岩要塞」，18 條，全量型（不是 MVU 卡）。涵蓋同一人三條（中文、英文停用版、行為模式）、兄弟共用劇情線、疑似玩家條目 `{{USER}}`、介面＋機制混合條目（uid 12，可收合狀態欄＋天數里程碑）、空內容版本標記。
- `clean-hero-roster.json`：「冒险者公会 灰港编年史」，57 條，增量 MVU 卡。15 位人物（含共用關鍵字「断岩」的兩人、不在狀態樹裡的創世者）、常駐角色概览合集、`[initvar]`／`[mvu_update]` 鷹架、EJS 15 條（9 條可辨識：5 條關係階段、2 條環境、2 條一次性事件；6 條認不出：隨機、迴圈、並列 if、沒有 `getvar` 來源）。
- 預期值：`<卡>.expected.txt`，由測試產生、人工審過才 commit。改程式造成差異時，先確認是預期的改變，再跑 `UPDATE_EXPECTED=1 cargo test --lib clean_cards` 重寫（值必須精確是 `1`，其他值不會寫檔）。
- 離線驗不到、要真桌與模型才看得到的：AI 重構的結果（拆幾人、合併、哪些不拆）、分支指認、回合尾字數、拒收自癒。
- 產生器不在 repo：它要讀原卡（不能入版控），放在作者本機 `TestCards/clean-cards-gen/`。
