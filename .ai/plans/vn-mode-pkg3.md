# vn-mode 包 3 方案：背景管線

總綱 [vn-mode.md](vn-mode.md) §6「背景」、§11 包 3 列；重用包 7 [取圖層與佇列](vn-mode-pkg7.md) §4。中案：不做方案送審，做完 Sol 驗收 1 次＋測試通道真生圖實測。核心立案估 250；主線開工重估約 400–450（含改光線、佇列共用、精靈預生），照流程上限只記不停工。本檔除標〔作者裁決〕者皆〔模型判斷·未裁決〕。

## 1 業界做法與我們的對應

| 業界 | 我們 | 差距 |
|---|---|---|
| Ren'Py `scene bg <地點>_<時段> with dissolve`；同地點畫早／午／黃昏／夜四張 | 背景庫鍵＝地點＋固定時段，換場淡入 | 一致 |
| Naninovel 背景＝具名 actor＋appearance 切換 | 同地點換時段＝同一基底的另一張 | 一致 |
| AI 修時段：img2img 低降噪或 ControlNet depth 鎖構圖、只改光線 | 雲端模型以既有基底圖當參考圖「只改光線」 | 沒遮罩、沒 ControlNet，構圖可能漂；「重生成背景」是保險絲 |
| AI VN 產品：背景預生＋依地點快取 | 精靈 ④ 預生首幕、回訪零成本 | 一致 |

## 2 定案設計

- **鍵**：地點文字經 NFKC、去頭尾空白、連續空白收一、轉小寫後取短雜湊（hex）當 slug；時段是固定列舉 `morning｜day｜dusk｜night`。檔名 `worlds/<id>/vn/backgrounds/<slug>-<時段>.png`；路徑只由（雜湊、列舉）組成，模型文字永不進路徑。`backgrounds.json` 記 slug → 原地點文字（顯示與選單用）。
- **時段正規化**：中英同義詞對照表（清晨／早上→morning、白天／中午／下午→day、黃昏／傍晚→dusk、夜／深夜→night 等）；`[bg]` 沒寫或認不得＝沿用同幕目前時段，再沒有＝day。GM 規範的 `[bg]` 那句改列出可用時段詞（同表情枚舉做法，zh／en 各一）。
- **觸發**：整幕格讀進來時，把本幕所有 `[bg]` 中背景庫沒有的排進佇列；串流中的暫定格不觸發（中斷的回合不替玩家花額度）。
- **生成**：庫裡同地點已有別的時段＝以那張當參考圖改光線；來源不收參考圖（API 參考圖未驗）就從零生。提示詞橫式、無人物、無文字，帶「只呼叫一次生圖工具」句；英文，放 `transport/vn_background_prompts.rs`。
- **來源與佇列**：沿用 `vn_sprite_source`（可改成中性名稱，發佈前不必相容）；背景走包 7 同一個一次一張的佇列（agy 並行 429），排在臉層工作前面。寫檔前重驗世界仍在，鍵已存在就不覆寫（除非是「重生成」）。
- **退路與顯示**：生成中＝前一張背景模糊＋地點字卡（第一幕黑幕＋字卡）；圖好且仍是目前格的背景才淡入。失敗自動重試一次，再失敗停在字卡，工具列選單有「重生成背景」。
- **精靈 ④**：開演時用開場狀態的 place／time 預生首幕背景。

## 3 實測（測試通道真生圖，截圖主線親看）

新 VN 桌 → ④ 預生 → 第一格直接是圖；同地點換時段 → 改光線、構圖目視相同；換新地點 → 模糊前景＋字卡 → 淡入；生成失敗 → 重試一次 → 字卡＋選單重生；重開 app → 庫命中、立即顯示。

**實測結果（2026-11-01，Codex 生圖，GM 文字照 harness 設定）**：五項全過。④ 一進來排首幕背景約 40 秒出圖並預覽，進桌第一格即是圖；同地點黃昏→夜晚以原圖改光線，構圖目視一致；換新地點時前一張模糊＋字卡，約 30 秒淡入；故意設壞 API 模型名，自動重試一次（AI log 兩次）後停在黑幕字卡、工具列重生成背景可按，換回 Codex 重生成成功；重開 app 進桌直接顯示、佇列為空。截圖在主線 scratchpad `real3/`。

## 4 觀察

- 立繪／背景共用的來源偏好鍵仍叫 `vn_sprite_source`（改中性名會連動前端設定，發佈前要改再一起改）。
- agy 背景生圖實測兩次都回 NO_IMAGE（約 1 分 48 秒，非 429）；重生成失敗時舊圖保留不受影響。
- 震動（shake）改成只震立繪與字卡層，背景不跟著震（背景若跟著重掛會每次重播淡入）。
- Sol 驗收建議採納：背景 PNG 覆寫改原子寫入（落檔中途失敗不截斷舊圖）。
- 地點字卡照模型原文顯示時段，模型寫英文時段詞（例：開場 `dusk`）字卡就是英文；genesis 已改要求用內容語言寫。
