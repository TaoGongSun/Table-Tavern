# grok-sprite-image-retest — 方案與實測（2026-11-14）

案別：大案（核心約 300 行、測試約 270 行；立案估 0 行只實測，實測通過後接進立繪來源而擴大）。碰到 spawn 旗標與共用對齊門檻，方案與驗收都送審（Sol）。

## 結論

Grok 加入立繪來源〔作者裁決 2026-11-14：實測可行就加入〕。2026-10-27 排除的理由都不成立了：當時 app 沒有內建去背又要求它出透明、app 沒把參考圖交給它、對齊門檻沒有真位移樣本。Grok CLI 1.0.77＋grok-4.7（生圖走 xAI Imagine，session 裡查不到確切模型版本）走 agy／API 同一條「淺灰底 → BiRefNet-lite 去背 → 臉框 → 裁頭重繪 → 羽化貼回」是通的。

實測（真 app 走測試通道，雄性獸人兩個角色，app 內 19 張＋夾具 2 張）：

| 項目 | 灰狼（無卡圖） | 虎（帶 1:1 卡圖） |
|---|---|---|
| 灰底 | RGB 約 220，標準差 <1.7，無漸層地板投影 | 217，標準差 <0.7 |
| 去背 | 毛尖完整、無灰邊 | 條紋與頭巾邊乾淨；超出輪廓的長鬍鬚被剪掉 |
| 每次呼叫張數 | 恰 1 張 | 恰 1 張 |
| 四表情 | 喜哀怒驚都到位，怒不過度 | 同左；驚 4 張裡 3 張因肩膀被整塊重畫而重骰 |
| 定稿比例 | 2:3 | 卡圖貼 2:3 灰畫布後回 832×1248 |
| 單張耗時 | 定稿 67s、表情 18–27s、變體 71s | 定稿 29s、表情約 36s、變體 132s |

對齊門檻用 12 張真實傾印重放：首次通過率 4/12 → 10/12，舊門檻會過的 4 張輸出逐位元不變；接縫 5 倍放大看不出來。

下緣加高 25% 對沒鬍子的人臉偏多（多蓋到脖子與領口），對有鬍子的人臉剛好；兩者領子都沒被重畫。Grok 回圖有方向不固定的 ±1 px 偏移，補正都蓋得住。看圖定臉框一次 33–118 秒。

## 做法

1. **來源**：`sprite_source` 白名單加 `grok`，`transparent()` 維持只有 codex；前端 `imageSources` 列出 Grok。房間生圖只走 API 不變。
2. **參考圖通道**：Grok headless 沒有附圖旗標，提示詞寫參考圖絕對路徑並指名 `image_edit`。參考圖一律壓成灰底 JPEG（變體送的是透明身體圖；看圖那條讀檔時整張圖會以 base64 進串流事件，原尺寸 PNG 撞單行 1 MB 上限）。
3. **生圖工具鎖**（spawn 旗標）：Grok 生圖呼叫加 `--disallowed-tools`＝聊天要拆的工具全集扣掉 `image_gen`、`image_edit`，並固定 `--reasoning-effort medium`。這條套用到所有 Grok 生圖（含既有的角色卡生圖），比原本「工具全開＋`--always-approve`」更小。單拆 `read_file` 不行：CLI 會因 `search_replace` 缺讀檔工具拒絕開 session。
4. **看圖（臉框）**：新增 `grok_vision_args`：工具只留 `read_file`（`--allow read_file`，其餘照聊天整包拆掉）、`--max-turns 3`、`--reasoning-effort low`；system 併進正文（不併 Grok 回「沒收到對話」）。提示詞是 app 固定文字，圖是 app 自己產的立繪。
5. **臉框問法**：Grok 直接看整張圖回框不穩（IoU 0.47）。改成只送立繪頂端正方形、疊上帶刻度的洋紅格線再問框（`vn_sprites/grid.rs`），IoU 0.75–0.86；下緣再加高 25%（張嘴時下巴會掉出框外；人臉 5 次有 2 次下緣停在下巴上方，加 25% 才包到）。問四個點再換算（Grok 自己的建議）實測沒有更穩，不採用。agy、codex 的問法與解析不動。
6. **卡圖轉 2:3**：改圖工具沿用參考圖比例，送出前把卡圖／封面置中貼到 2:3 淺灰畫布（`compose::portrait_canvas`），提示詞說明灰色是待畫滿的空白。只在 Grok 來源做。
7. **對齊門檻（共用，codex／agy 也走）**：舊規則「±8 px 搜尋的最佳位移必須是 0」在沒有真位移樣本時訂的，虎的四組分數（原位→最佳）是 12.50→12.43、15.11→9.94、13.37→10.84、12.98→12.81——兩組只差約 1%（取樣雜訊）就被擋，另兩組是真的 1 px。改成 `compose::settle`：
   - 原位就是最合：照舊。
   - 最合處超過 ±2 px：拒收重骰（照舊）。
   - 最合處在 ±2 px 內但分數沒低到原位的 95% 以下：當雜訊，仍算原位、照環帶比例判（實測雜訊級贏幅 0.6–3.3%、真位移 18.9–34.3%）。
   - 明顯更合且在 ±2 px 內：把回來的圖平移補正，以補正後的環帶比例判，臉層取自補正後的圖。
   - 環帶比例上限 5% 不變；變體身體（`shared_body`）維持「別處更合一律拒收」。
   - 原本會過的輸入，輸出逐位元不變；差別只有「原本被重骰的小位移改成補正」。

8. **測過的版本**：Grok 生圖旗標改了，CLI 夾具照 contract_tests 慣例整套重錄成 1.0.77，`tested_versions` 的 grok 跟著改成 1.0.77（新安裝釘這版；還在 1.0.70 的玩家會看到一次「比測過的舊」提示）。

## 已知限制

- 條紋等花紋當眉毛的角色，換表情時額頭花紋會跟著變（眼睛以上約 35% 像素變動）；提示詞加「花紋不變」實測沒有改善，已拿掉。
- Grok 偶爾把肩膀、身體整塊重畫，被門檻擋下後重骰。
- 人臉側轉那一邊的臉頰，臉框 5 次只包到 1 次；要玩家手調。
- 臉框左右緣偶爾切到眼鏡鉸鏈幾個像素（5 次有 3 次），落在羽化帶內、實測沒有錯位。
- 髮絲圈住的小塊灰底去不掉（髮梢淺邊已由 [sprite-matting-defringe](../handoffs/sprite-matting-defringe.md) 修掉）。

- 粉色系角色碰上洋紅格線沒測；有卡圖的變體、長髮蓋到臉上沒測。
- Grok 沒有 seed、遮罩、尺寸與透明參數；長期一致性靠參考圖。
- 超出毛邊輪廓的細長鬍鬚會被去背剪掉。
- 構圖常畫到膝蓋或腳踝，不是提示詞要的小腿中段。
- Windows、背景生圖、封面當畫風參考那條沒測；codex／agy 在新門檻下沒有位移樣本。
- Grok 訂閱 2026-11-20 到期後這條來源無法再回歸測試。

## 觀察

- 帶卡圖時定稿只沿用卡圖的外觀，卡沒宣告畫風就一律用通用動漫畫風句（各來源共通的既有設計）；半寫實卡圖會拿到畫風較平的立繪。

- 失敗的表情格在立繪分頁顯示「尚未生成」，沒標失敗。
- app 自己的 grok-home 在測試 root 是未登入狀態，實測時複製了終端機的登入檔，測後已刪。

## 業界做法與差距

業界臉部定位用專門的偵測與特徵點模型，表情用遮罩局部重繪並容許 1–2 px 再由羽化吸收；我們只有雲端 CLI，靠裁頭＋格線讀座標＋位移補正來補。
