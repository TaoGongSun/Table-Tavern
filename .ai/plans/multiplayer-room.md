# multiplayer-room — 多人跑團房間計畫（2026-11-02 立案版，v1＝桌面版當 GM 執行端）

立案說明見 [tasks/multiplayer-room.md](../tasks/multiplayer-room.md)。作者 2026-11-02 拍板的事標〔作者裁決 2026-11-02〕，其餘設計標〔模型判斷·未裁決〕；拍板清單見 §11。大案：方案與每包驗收依規約送 Sol。

## 0 定位

幾個真人玩家＋AI GM（＋AI 扮演的 NPC 卡）在同一個房間裡跑團，**所有人用手機玩，包含出額度的人**。產品形態：出額度者在家裡的電腦開著桌面版、建房 → 丟連結給朋友 → 大家用手機進來 → 回合制推進。只有**出 GM 額度的人**（下稱「出額度者」）要在桌面版設定一次 AI；其他玩家開連結、填名字、選角色就能玩。〔作者裁決 2026-11-02：設定極簡、一鍵〕

兩段路線〔作者裁決 2026-11-02〕：
- **v1＝桌面版當 GM 執行端**：GM 那一發由出額度者的桌面版打，伺服器只做中繼與回合裁判。桌面版既有的 Rust GM 引擎、世界書、換幕摘要、NPC 點名、OpenRouter 一鍵授權、官方命令列工具通道全部直接沿用，GM 不移植。訂閱額度（Claude、Gemini、Codex、Grok）因此能用。
- **v2＝伺服器代打**（另行立案）：給沒有任何人有桌面版在線的純手機群；GM 回合移植成純 TS 跑在伺服器，出額度者的金鑰經伺服器。v1 的協定要留這個位子（執行端是一種角色，桌面版與伺服器內建都能扮）。

不是桌面版的功能延伸也不是網頁版的：兩者都是「資料只在自己裝置、沒有伺服器」，房間必須活在大家都連得到的地方。

## 1 誰出額度、誰設定

- **出額度者在桌面版設定一次，其他人零設定**。其他玩家不會看到任何供應商、模型、金鑰字樣。〔作者裁決 2026-11-02〕
- **一幕一個執行端、一個供應商＋模型**。GM 一回合只打一發，所以一幕只能有一個付費方。換幕可換執行端（換成另一位有桌面版在線的玩家）、換供應商、換模型，三者都是幕設定。〔作者裁決 2026-11-02：同一幕固定、換幕可換〕
- 換幕是好切點：桌面版換幕本來就把前面劇情壓成摘要帶進下一幕，換供應商不會有「對方沒看過前面」的問題，提示詞快取也不會被打壞。
- **例外**：幕中 GM 被拒答（審查）、額度撞上限或連續失敗時，允許出額度者從手機當場切路線／模型重送這一回合，不必等換幕。這是唯一的幕中切換。〔模型判斷·未裁決〕

## 2 v1 執行端：桌面版開著、人不在電腦前〔模型判斷·未裁決〕

那台電腦就是放在家裡的 GM 主機。成立的理由：桌面版對伺服器是**往外連**的 WebSocket，不需要固定 IP、不開防火牆、不設路由器；命令列工具本來就是桌面版在背景非互動地呼叫；螢幕鎖定不影響程序，只有睡眠會斷。

要做的事：
- **防休眠**：桌面版「房間模式」開啟時阻止系統睡眠（Windows `SetThreadExecutionState`、macOS `caffeinate` 或 IOPMAssertion、Linux `systemd-inhibit`），退出房間模式解除。Windows 更新重開機擋不住，靠下一條。
- **斷線重連**：執行端斷線自動重連並認回自己的房間（執行端憑證，見 §8）；期間手機端顯示「GM 主機離線，等待中」，回合不結算。
- **無人值守的錯誤上送**：現在桌面版遇到工具升版格式不對、額度用完、拒答是跳提示給人按；房間模式下這些要變成結構化事件送到房間，由出額度者**在手機上**按「重試」「換模型」「切 OpenRouter」。協定因此多一組「出額度者遠端控制自己執行端」的指令，只有配對過的本人能發。
- **額度節奏**：訂閱是時段制上限，多人吃得比單人快；手機端要看得到執行端回報的額度狀態與重置時間，撞上限能臨時切 OpenRouter 繼續。
- **執行端狀態面板**：桌面版房間模式只需一個小面板（房間碼、在線玩家、目前模型、最近錯誤、退出），不必在桌面版重畫整個房間介面；要看劇情用手機。
- 執行端收到的是「這一回合的玩家行動批次」，回的是 GM 旁白（含點名）與被點名 NPC 的接話，流程沿用 `chat_turn::gm_narrate`／`chat_with_character`；多玩家合併進提示見 §10 包 3。

## 3 一鍵接供應商

v1 走桌面版既有連線，不另做探測邏輯：
- **境外**＝OpenRouter 一鍵授權（已有，涵蓋 Claude、Gemini、DeepSeek 等，也有免費模型），或官方命令列工具（已有，Claude／Codex／Gemini／Grok 訂閱可用）。
- **境內**＝桌面版新增「中國供應商」設定（§10 包 5）：矽基流動貼金鑰（中國供應商沒有給第三方用的 OAuth），沿用 OpenAI 相容通道的 `base_url` 設定；免費模型排序寫死、免費失敗絕不自動升付費（沿用 cn-web-provider 兩項裁決）。
- 出額度者看到的是桌面版現有的「連接 AI」頁多一個「中國供應商」選項；選完就能開房。「境內境外由 app 內部處理」在 v1 落成：房間裡只顯示「GM：某模型」，其他玩家不知道走哪條線。〔作者裁決 2026-11-02 的「一鍵」在桌面版已成立〕
- v2 的伺服器代打才需要客戶端探測境內境外與供應商轉接層（疊在 cn-web-provider 的網頁版設定層上）。

**訂閱的事實**：Gemini／Claude 的訂閱沒有 API 額度，v1 靠桌面版的命令列工具才用得上；v2 伺服器代打用不了訂閱，只能 API 金鑰或 OpenRouter。〔開工時對一次官方條款〕

## 4 成人內容與審查退路〔作者裁決 2026-11-02〕

- 預設玩家都有 VPN，出額度者改走境外供應商，是審查過不了時的極端退路。app 的責任：境內被拒答時明確告知原因、給「切境外重送」一鍵，不靜默重試到失敗。
- **境外也不是全通**：Claude 與 Gemini 對露骨色情同樣會拒；寬鬆的是 OpenRouter 上各家開源模型與部分第三方託管。模型清單標「寬鬆度」（粗分三級，手寫維護）。〔模型判斷·未裁決〕
- **兩種帳號風險都落在出額度者**：中國供應商的封號；拿訂閱額度透過命令列工具服務他人，比單人使用更明確地踩在各家條款邊上。桌面版啟用命令列通道時已有風險說明，房間模式要再補一句「額度會被房間裡其他人消耗、條款風險自負」。

## 5 回合：何時觸發 GM〔模型判斷·未裁決〕

回合制為主幹，三種結算方式並存：

```
GM 旁白（可點名 NPC 卡接話，沿用桌面版機制）
 → 每位玩家一格「本回合行動」，送出前可改，可按「跳過」
 → 結算條件三選一先到先算：全員已行動或已跳過 ／ 房主按「結算」 ／ 倒數到期
 → 伺服器把行動合併成一批（固定順序：加入順序；可選每回合隨機）派給執行端
 → 執行端生成、串流經伺服器廣播給所有人 → 下一回合
```

- **跳過鈕**與**房主提前結算**必要，否則一個人離開全桌卡死。
- **倒數**是開房設定、預設關閉。同步玩開 60–120 秒；非同步玩不開。到期：有草稿就自動送出，沒有算跳過，並讓 GM 知道「某某這回合觀望」。不靜默吃掉。
- **不做「任何人發言就觸發」**：GM 會一直回最快的人、成本線性暴增、兩人同送會撞到正在生成的 GM。
- **併發規則**：一房同時只有一個 GM 請求在飛；回合編號當版本號，過期回合的送出退回；玩家在 GM 生成中可以先打字，不能送。
- 中途加入：下一回合才算在場，GM 旁白補一句登場。中途離開：角色暫由 GM 當 NPC 或標記離席，房主決定。
- NPC 卡照桌面版 GM 點名接話，一回合接話上限沿用 `max_round_speakers`。

## 6 伺服器：為什麼要、放哪、做什麼

**要**。手機跑本地模型當 GM 不可行；手機連不到家裡的電腦（NAT），P2P 在中國行動網路要 TURN 中繼等於還是伺服器，房主離開房間就死。伺服器是中繼點，v1 不打 AI、不持有金鑰。

**放哪**：選丙。〔作者裁決 2026-11-02〕

| 選項 | 做法 | 好處 | 代價 |
|---|---|---|---|
| 甲 | Cloudflare Workers＋Durable Objects，一房一個 DO，WebSocket 同步 | 跟網頁版同一家、作者自己部署、零維運、按量近乎免費 | 大陸無 VPN 不穩（pages.dev 調查 34 測點通 22）；成人向玩家本來就假設有 VPN |
| 乙 | 朋友在中國架 VPS（Node 版） | 大陸連得穩 | ICP 備案、朋友維運、AGPL 向使用者提供原始碼、營運責任落在朋友 |
| **丙（拍板）** | 甲先做，伺服器核心寫成可同時跑在 Workers 與 Node 的純 TS，最後一包補 Node 薄殼 | 不鎖死 | 多一層抽象 |

v1 伺服器做四件事：房間與成員、回合裁判、執行端配對與派工＋串流轉播、房間紀錄的保存與匯出。不做帳號系統（房間碼＋暱稱＋裝置識別），不持有任何平台帳號或金鑰。v2 在同一套協定裡加「內建執行端」。

## 7 落點

- **手機客戶端**：同 repo 獨立 `party/` package（照 `web/` 的樣子，自己的 package.json、vite、vitest），客戶端與 Worker 一起部署（Workers Static Assets）。純 TS 底層用路徑別名從 `src/` 與 `web/src/` 直接引（卡片顯示、存檔契約、i18n、卡片介面沙盒）。〔作者裁決 2026-11-02〕不進網頁版：網頁版已裁決「一桌一張卡、GM 不進」〔作者裁決 2026-09-30／10-07〕。
- **桌面版執行端**：前端 `src/features/room/`，Rust 新 domain 模組 `room`（照 STRUCTURE 先單檔再升格），`commands/` 只做邊界。GM 引擎不動。
- 手機殼：沿用 cn-web-provider 階段 2 的 Capacitor 結論；`party/` 是 PWA 等級，可先不包殼。

## 8 信任邊界與資料〔模型判斷·未裁決〕

- **v1 伺服器不碰金鑰**：金鑰留在出額度者的桌面版，從未離開那台電腦。這比原案（金鑰經伺服器）小一圈。
- **執行端配對**：桌面版建房時產生房間碼＋執行端憑證（伺服器簽發、存桌面版本機）；伺服器只把該房間的派工送給持有該憑證的連線。出額度者的手機要拿到「出額度者身分」得輸入桌面版顯示的一次性配對碼，之後遠端控制指令只接受這個身分。
- **派工內容**：伺服器送執行端的是玩家行動文字＋在場名單，不是提示詞；提示詞在桌面版組。玩家文字是信任邊界輸入，執行端照既有玩家輸入路徑處理。
- 房間紀錄：對話、幕摘要存在房間（DO storage）；房主可匯出成網頁存檔契約（桌面版已能匯入）帶走。桌面版執行端本機也留一份桌檔（它本來就是一張桌）。閒置 N 天自動清。
- 玩家身分：暱稱＋裝置隨機識別碼（localStorage），換裝置由房主重新指派角色；不做登入。邀請連結＝房間碼＋一次性加入密鑰，房主可重生。
- 伺服器不審內容；AGPL 義務見任務檔。

## 9 中國生態的實際約束（記下，不做實驗）

- 微信內建瀏覽器點邀請連結：擋 APK 下載、WebSocket 多半正常；要「用瀏覽器開啟」引導。
- 華為純血鴻蒙裝不了 APK，只能走網頁。
- 中國安卓沒有 Google 推播，非同步跑團的「輪到你了」通知要接各廠商推播，MVP 不做；開著 app 走 WebSocket，不在線靠群組喊人。
- 境外版（伺服器與供應商清單換地區）同一套程式，等可運行版本做完再說。〔作者 2026-11-02 告知〕

5. v1＝桌面版當 GM 執行端（出額度者電腦開著連網即可、人用手機玩），v2＝伺服器代打另行立案。

7. 玩家行動結算前即時公開。
8. 手機端 v1 不顯示卡片介面，列已知限制。

## 12 觀察（範圍外，不立案）
- 桌面版 OpenAI 相容通道已有 `base_url` 設定（`transport/client.rs`），境內供應商在桌面版是設定層的小包；cn-web-provider 做的是網頁版那層，技術上只有 v2 依賴它。
- 本機實機驗收（2026-11-02，claude-haiku 當 GM）：開場旁白替已入座的真人玩家卡（吟遊詩人）說了台詞，多人段指示在、模型沒守；低階模型的遵守度，換幕或換模型時再看。
- 模型把「下一位：X」寫在狀態欄圍欄之前時，串流中會閃過這行（手機與桌面版同，`streamDisplayText` 只截圍欄與標籤），定稿後消失。
- 手機故事串不顯示「某某觀望」：觀望標記只落在桌面版逐字稿，伺服器 `story` 不帶。

## 13 包 7 方案：Node 自架殼〔模型判斷·未裁決；Sol 方案審 1 輪，必改 2 條已併入〕

**目標**：同一個 `party/server/core/` 跑在一般 Node 主機上（一個程序、一個 SQLite 檔），行為對齊 Workers 殼；手機客戶端與桌面版執行端不改。核心估 **約 250 行**（立案 150 偏低：store＋鬧鐘＋連線管理＋路由＋靜態檔＋設定各要一塊），測試約 250。

**落點**（`docs/STRUCTURE.md` 已預留「同層另一個資料夾」）：`party/server/node/`
- `index.ts`：設定、`node:http` 伺服器、路由（照 `workers/index.ts`：建房＋重產碼 5 次、房間路徑正規式、export 只收 GET、成員 WS 驗 `Origin`）、靜態檔、`ws` upgrade、SIGTERM。路由約 30 行與 `workers/index.ts` 重複，刻意不抽象（`Request` 與 `IncomingMessage` 兩套型別，抽了比重複長）。
- `rooms.ts`：房間表 `Map<code, Room>`，`Room` 持有 `RoomRunner`＋該房連線；實作 `Connections`／`Alarm`；成員心跳與掃描；閒置卸載。
- `sqlite-store.ts`：`RoomStore`＋鬧鐘持久化。
- 測試同住 `node/`；`check-structure` 的 `party/server` 規則已容許。

**三個介面**
- `RoomStore`：**單一 SQLite 檔**（`node:sqlite` 的 `DatabaseSync`，WAL），表照 DO 三張再加房間碼欄：`room(code PK, state)`、`cards(code PK, cards)`、`events(code, seq, at, type, payload, PK(code, seq))`，另加 `alarms(code PK, at)`。`commit` 一筆 `BEGIN…COMMIT`；`deleteAll` 在一筆交易刪該房四表的列。選單檔不選一房一檔（可原樣重用 `SqlRoomStore`）：自架者只要備份一個檔；重用要把 `SqlRoomStore` 從 workers-types 搬開、改動 Workers 殼，不划算，重複約 40 行 SQL。
- `Connections`：`list()` 回該房在 `Room` 裡登記的 `ws`；`send`／`close` 包 try（同 DO 的 `tryIt`）。
- `Alarm`：`set(at)` 先寫 `alarms` 表再排 `setTimeout`；`null` 刪列清計時器。`setTimeout` 上限 2³¹−1 ms（約 24.8 天，閒置天數可到 365），超過就排到上限、醒來 `now < at` 再排一次。到期 → 先跑成員掃描、再 `runner.run({ kind: "alarm" })`（照 `RoomDO.alarm`）。

**序列化與重啟續跑**
- 每房一個 `RoomRunner`，它本身就是每房序列化佇列（協定 §14-1）；同房所有輸入（HTTP、訊框、斷線、鬧鐘）都經 `runner.run`。不同房間互不等。`DatabaseSync` 同步呼叫在單執行緒內本來就不交錯。
- 房間懶載入：第一次有請求或鬧鐘才建 `Room`；`runner` 首步 `load()`＋把狀態裡已不存在的連線補離線（既有邏輯），程序重啟後即等同 DO 喚醒。
- 啟動掃描：`room` 表 LEFT JOIN `alarms` 全部排回計時器（過期或缺列的立刻跑，醒來由核心重算 `nextAlarm`）。`nextAlarm` 一定含閒置期限，所以每個存活房間都會被掃到。
- 已知限制：狀態與鬧鐘分兩次落地（`RoomRunner` 先 commit 再 `alarm.set`，同 DO）。程序在兩者之間崩潰時，`alarms` 留舊值：舊值較早只是早醒一次重算，較晚則該次計時晚到；缺列由上面的 LEFT JOIN 補。
- 卸載（對應 Hibernation）：每次取得 `Room` 就在第一次 await 前把工作數 +1，涵蓋整段掃描＋`runner.run`，`finally` 再 −1；只有「沒有連線且工作數為 0」時，同步核對 Map 裡仍是同一個 `Room` 才移除，避免舊 `Room` 的回呼醒來時與新 `Room` 兩個 runner 寫同一房。串流緩衝與頻率桶隨卸載丟失，與 DO 被逐出相同（協定 §4.3 已容許）。鬧鐘計時器只記房間碼，到期再按碼重新取 `Room`。

**連線與信任邊界**
- 錯誤收尾：每條 `ws` 的 `error` 與 `close` 共用一個可重複呼叫的斷線收尾（只送一次 `disconnect`）；`ws` 擋下超大或非法 UTF-8 訊框會發 `error`，不聽會讓整個程序退出。HTTP、upgrade、計時器三個入口都包一層，接住同步例外與 Promise rejection（HTTP 回 500、upgrade 毀掉 socket、計時器記 log），一房出錯不影響其他房。
- `ws`（Node 沒有內建 WebSocket 伺服器；業界標準）`noServer` 模式，`maxPayload` 1 MiB＝平台上限（成員 16 KiB 由核心 `validate` 擋）；二進位訊框當 `""` 交核心（同 DO）；`ws` 預設會擋非法 UTF-8。
- 成員心跳：殼攔截字面 `{"t":"ping"}` 直接回 `{"t":"pong"}` 並記時間戳，不進佇列（對齊 DO 自動回應不喚醒）；每次該房有訊框或鬧鐘時，照 `RoomDO.sweep` 關掉 45 秒沒心跳的成員（1001）並送 `disconnect`；另每 15 秒全域掃一次（DO 沒訊框也靠鬧鐘醒，Node 補這個是因為死 TCP 不一定有 close 事件）。執行端 `hb` 照常進核心。
- 建房 body 上限 16 KiB（串流讀到超過就 400）；房間碼不合格式 404、不建 `Room`。
- 靜態檔：Node 自己服務（不全交給 Caddy：區網自用沒有反向代理時，手機仍要從這台載客戶端）。`/api/*` 先走路由，其餘從 `party/dist` 回檔；`decodeURIComponent` 失敗回 400；`resolve` 後用 `path.relative` 判斷（不得以 `..` 段開頭、不得是絕對路徑），按路徑分段而非字串前綴，擋穿越；找不到檔 → `index.html`（`/r/<碼>` 單頁）；小型 MIME 表；`/assets/*` 帶 `immutable` 快取。不加依賴。
- 建房限流：程序內每 IP 滑動視窗，**真的照協定每小時 10 次**（Workers 只能近似每分鐘 1 次）；過期桶定期清。IP 預設取 socket 位址；`TRUST_PROXY=1` 才取 `X-Forwarded-For` 最右一段（反向代理加的那段）；前提是代理一定補寫這個標頭，且 Node 只聽 127.0.0.1 或被防火牆擋住、外部無法繞過代理直連，這兩點寫進檔頭的部署範例。

**TLS 與網址**：Node 只講 http，不碰憑證。對外一律放在反向代理後（Caddy 自動 HTTPS 一行 `reverse_proxy`，nginx 要設 `Upgrade` 標頭），檔頭註解附 Caddy 範例；區網自用可直接 http（桌面版已放行私網 http）。`PUBLIC_ORIGIN`（例 `https://party.example.com`）決定邀請連結與成員 WS 的 `Origin` 比對，**不從 `Host` 標頭推**（客戶端可控，會削弱來源檢查）；沒設預設 `http://localhost:<PORT>` 並在啟動時印警告。

**設定（環境變數）**：`PORT`（8787）、`HOST`（127.0.0.1，區網自用改 0.0.0.0）、`PUBLIC_ORIGIN`、`TRUST_PROXY`、`ROOM_IDLE_DAYS`（30，1–365 同 Workers）、`DB_PATH`（`./data/rooms.sqlite`）、`STATIC_DIR`（`party/dist`）。

**啟動與建置**：核心是無副檔名 import，Node 型別剝除跑不了，用既有的 Vite 打包（`build.ssr`，`vite.node.config.ts`，輸出 `party/dist-node/`、gitignore），`ws` 外部化；`npm run build:node`、`npm run start:node`。不加 `tsx`。新依賴：`ws`（執行期）、`@types/ws`、`@types/node`（開發）；`engines.node >= 22.13`（`node:sqlite` 免旗標起點）。型別檢查加第三份 `tsconfig.node.json`（`types: ["node"]`，含 `server/core`＋`server/node`），`tsconfig.json` 排除 `server/node`；順帶證明核心沒漏用 Workers 型別。`typecheck` 腳本三份都跑；verify 的 party 步驟不改（它已跑 test／typecheck／build）。

**與 Workers 殼的行為差異**：見協定 [§15](multiplayer-room-protocol.md)。

**實作結果**：核心約 400 行（http 139、rooms 138、sqlite-store 77、main 37、Vite 設定 10），測試 205。超出估計的主要是 Sol 必改兩條（錯誤收尾、卸載工作計數）與靜態檔。實跑：Node 殼＋測試通道桌面版＋瀏覽器手機，建房、配對入座、一回合，SIGTERM 後同一 DB 重開，桌面版自動接回，手機再跑一回合（GM 串流與 NPC 接話正常）。

**測試計畫**（`node/*.test.ts`，真 `ws`＋`node:sqlite` 暫存檔，port 0）
- store：兩房互不干擾、commit 交易（events 與 state 同進同退）、`deleteAll` 只刪該房、名冊只在變更時重寫。
- 端到端：HTTP 建房 → 執行端與成員連線 → `ev` 送出當下該列已落地 → 關伺服器、用同一 DB 重開 → 序號接續、狀態接回、舊連線補離線。
- 鬧鐘：重開時掃描排回；超過 2³¹−1 的期限被夾住再排（注入假 `setTimeout`）。
- 錯誤收尾：超大訊框、非法 UTF-8、畸形 `%` 路徑之後，程序仍在、另一房照常操作。
- 卸載競態：用可控制的 await 讓舊 `Room` 停在掃描中途、連線全斷後重連，驗證不會出現第二個 runner（舊回呼醒來後仍用同一個 `Room`）。
- 邊界：成員 `ping`→`pong` 不進核心、45 秒沒心跳被 1001；建房第 11 次 429；成員 WS 錯 `Origin` 403；超大訊框被 `ws` 擋；靜態檔 `/r/<碼>` 回 index、`/../` 穿越被擋。
- 實跑：`npm run build && npm run build:node && npm run start:node`，桌面版測試通道連 `http://localhost:8787` 建房＋瀏覽器手機加入跑一兩回合。
