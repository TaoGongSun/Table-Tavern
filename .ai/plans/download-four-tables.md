# download-four-tables — 設計方案

Fable 網頁設計審查員提出，第 6 節為拍板；其餘細節〔模型判斷·未裁決〕。

## 先講框架
- 四種桌對網頁版訪客不對等：「開新的一桌」網頁版就有（單卡、世界書、卡片介面兩邊皆有），另外三種是桌面版限定。頁面說成「你在網頁玩的是第一種，桌面版再多三種」，不把四種並列當新功能賣。
- 頁面順序與用詞照大廳四格（開新的一桌／一句話開桌／開房間／視覺小說，同圖示同字），玩家裝完看到的就是同一排東西。
- **三語同一套結構與截圖清單**，各語系只換文字與截圖語言〔作者裁決 2026-11-06：「之前簡中和繁中、英文的下載頁面介紹是不同的，這次趁機統一。」〕。簡中專屬的房間主軸（`ROOM_TOUR_ZH_CN`、`rooms` 分支、只認簡中圖的退圖示卡規則）整個拿掉。

## 1. 結構：四扇門＋單一詳情面板（同頁分頁）
由上而下：
1. **主視覺**：標題、一句導語、第一組下載鈕、版本行；右邊放大廳截圖。理由：一張圖同時說明「有四種開法」和 App 長相。
2. **四扇門**（選擇器）：桌機一排四張、手機 2×2。每張＝大廳同款圖示＋桌名＋一行「適合：…」＋小標「網頁版也有」或「桌面版限定」。這排就是五秒看懂四種差在哪的地方，不點也能挑。
   - 開新的一桌：手上有酒館角色卡、想自己擺角色。
   - 一句話開桌：沒有卡，想馬上開玩。
   - 開房間：想和朋友一起，朋友用手機加入。
   - 視覺小說：想看 AI 畫的場景與立繪，用選項推進。
3. **詳情面板**：一次只顯示被選的那一種，預設「開新的一桌」（大廳順序）。點門切換、手機上順便捲到面板頂。網址 `#download/<桌>`（new／oneLine／room／vn），可分享、說明書能連回房間那格。理由：四種各 2–3 張大圖，長捲會到十幾屏；分頁讓頁面維持約四屏，比較資訊已在門上。
4. **每種桌都有**（圖示卡一排）：用你的 AI（訂閱或額度）、資料在自己電腦、換幕與前情提要、編輯角色卡與世界書。
5. **網頁版和桌面版差在哪**（瘦身後的對照表）。
6. **安裝被擋怎麼辦＋第二組下載鈕**（照舊）。

不採：獨立子頁（多一套路由與返回邏輯，超出中案預算）；純長捲（太長）；手風琴（手機展開時圖文跳動）。
實作備註：`download-route.ts` 的 `useHashPage` 改成 `#download` 前綴比對；房間面板放手機直式圖，`DownloadPage` 寫死的 1600×1136 改成每張圖自帶寬高；`pickTourImage` 改成三語都找自己語言的圖、缺圖退英文圖。

## 2. 每種桌的面板內容
每個面板＝一句導語、三點重點、截圖（一大一小或兩張並排）、一行「網頁版：有／沒有」。截圖鍵見第 5 節。

- **開新的一桌**（網頁版也有）：匯入酒館角色卡與世界書；桌面版多了多角色同桌、GM 旁白與指定誰接話；數值由 App 記（狀態欄）。截圖 T2、T3。
  - **卡片介面小節**（同面板下半）：酒館卡附的介面（狀態面板、按鈕）照樣跑；要玩這類卡就開這種桌。截圖 T4。
- **一句話開桌**（桌面版限定）：一句描述＋題材按鈕 → AI 生大綱；先看大綱、改了再開桌；生出世界、角色與開場。截圖 T5、T6。
- **開房間**（桌面版限定）：房主電腦當 GM、朋友手機點連結就進、不用裝；每人每回合寫行動、到齊一起結算；AI 額度房主出，選免費模型不花錢。截圖**借說明書** G04（房主桌面）＋G15（朋友手機）並排。面板底放「看完整玩法說明」連 `#guide/room`；說明書頁首加「回到下載頁」連 `#download/room`。
- **視覺小說**（桌面版限定）：AI 寫劇本、畫背景與立繪；用選項推進；時段與天氣會變；作品可匯出給別人看。截圖 T7、T8。

## 3. 現有內容怎麼併
- **特色卡**：`oneLine`、`status` 移進各自面板；`subscription`、`editor` 改成「每種桌都有」的圖示卡，截圖退役刪除；`scenes`、`local` 維持圖示卡。`roomHost.zh-CN`（舊版房間對話框）、`roomGuest.zh-CN` 刪除。
- **功能對照表**：各桌專屬列（multi／room／vn／oneLine／status）拆進面板的「網頁版：有／沒有」行；表格只留不屬於某一種桌的列（存檔、AI 來源、更新、角色卡／世界書／卡片介面、圖片、用量、主題、贊助、重構、換幕、編輯器）。
- **標題與導語**：三語改成同一個意思（桌面版＝四種開桌方式，沒有每日次數上限）；現在簡中的房間主軸標題作廢。
- **安裝步驟、兩組下載鈕**：位置不變；簡中頁頭的「看完整玩法說明」鈕拿掉，改由房間面板帶。
- **文案**：門的桌名沿用大廳既有鍵；「適合」行、面板重點、房間段都是新字典鍵，要寫十語系（非核心行數）。

## 4. 簡中保留的差異（只差文字與按鈕，不差結構）
- **下載鈕只給 pCloud**、版本行用建置版號（現狀照留）。理由：GitHub 在中國連不上，給 GitHub 鈕等於給死鈕。網頁版選中國供應商（`cn`）時不分語系也照現狀只給 pCloud。
- **AI 來源相關文案**（導語、「用你的 AI」圖示卡、對照表 AI 列）：簡中改寫成國內可直接用的路線（桌面版支援的硅基流动等），不主打 OpenRouter／Claude／ChatGPT 訂閱。理由：國內玩家多半用不了那幾家，主打它們會讓人以為桌面版在國內不能用。實際支援清單由施工者照 `src/features/ai-connection/` 確認後寫。
- 其餘（四扇門、面板、截圖清單、說明書）三語完全一致。

## 5. 截圖清單（拍照者照這節拍）

### 共通規則
- 走測試通道（`npm run harness:build`＋`node scripts/harness.mjs`，獨立 `--root`）。桌面圖：視窗 800×600，輸出 1600×1136；手機圖：600×1300（同現有說明書手機圖）。
- 每張拍三語：zh-TW、zh-CN、en。App 介面語言＝該語系；故事內容（AI 生成的文字、角色名）也要是該語系。
- 示範角色一律男性，主角用雄性獸人；內建範例「迷霧酒館」（狐狸、騎士、吟遊詩人）照用〔作者裁決 2026-11-06〕。
- 畫面乾淨：沒有通知條、更新紅點、錯誤訊息、開發者工具；邀請連結網域是 `tt-room.pirahus.com`，不得出現 127.0.0.1 或 localhost；不得出現帳號名、本機路徑、金鑰。
- 檔名：下載頁 `web/src/features/funnel/tour/<鍵>.<語系>.webp`；說明書 `web/src/features/funnel/guide/shots/room-<NN>.<語系>.webp`。
- 生成用模型選低階／免費檔位。
