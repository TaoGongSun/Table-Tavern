# initvar-yaml-list：樹模式 [initvar] 的 YAML 清單

## 現況（零 AI 重現，中性樣本；TestCards 四張帶 `[initvar]` 的卡都沒有 `- ` 清單）
`extract_initial_tree` 原本用 `parse_indented_fields` 逐行建樹：`- 純量` 沒冒號整行丟掉、`- 鍵: 值` 剝掉 `- ` 後同名互蓋（物件清單只剩最後一項）、根層 PyYAML 同欄 `- ` 丟掉、`[勇敢, 冷靜]` 存成字串。上游 MagVarUpdate（`util/common.ts` `parseString` → `YAML.parseDocument`）得到真陣列。

## 存法：陣列存成一片 JSON 葉子（三方審查通過）
| 之後怎麼讀寫 | JSON 葉子 | 索引分支 |
|---|---|---|
| GM `<UpdateVariable>` 索引路徑 | 走 `apply/array.rs` 的上游 splice 語意 | 視圖是物件：remove 留洞、insert `-` 落最小未用鍵 |
| 切變數模式物化、`edit_tree_if_events` 補初始化來源 | `restore_leaf` 還原成真陣列 | 變成物件 `{"0":…}` |
| 既有同類資料 | 行內 `[...]`、變數模式陣列、Upstream insert 新鍵都是 JSON 葉子 | 只有狀態區塊用 |

## 解析：initvar 清單模式
`transport/state_yaml/` 的剖析器加模式旗標，狀態區塊（`parse_state_fields`）行為不變；`parse_initvar_tree`（`initvar.rs`）供 `extract_initial_tree` 用，`[mvu_update]` 規則表仍用 `parse_indented_fields`。範圍依作者「避免過度施工，罕見邊際狀況列已知限制」縮減〔主線轉達作者要求 2026-10-12〕。initvar 清單模式：
- **不做狀態區塊的啟發式**：單鍵純量項不併成具名鍵、無冒號標題項是純量。
- **清單項判鍵值照 YAML**：只有 `: ` 或行尾 `:` 才算鍵；全形冒號、沒接空白的 `:` 是純量（`- 08:00 起床`、`- https://x`、`- 火球：造成10傷害`）。引號開頭先當純量（接 `: ` 才是引號鍵）；`{`／`[` 開頭當純量或流式值。具名鍵行先找 `: `／行尾 `:`，沒有才退回寬鬆的第一個 `:`／`：`；鍵剝引號。
- **空項佔索引**：`- ""`→`""`、只有 `-`→`null`、`- {}`→`{}`、`- []`→`[]`。清單元素裡 `鍵:`→`null`、`鍵: ""`→`""`、`鍵: {}`→`{}`。清單外值空的鍵照舊是空 Branch；清單外的 `鍵: ""` 存成空字串葉子。
- **引號**：帶引號一律字串；雙引號只解 `\"`、`\\`，單引號 `''`→`'`。
- **區塊純量** `|`、`>` 一律字串（內容同狀態區塊：逐行去縮排以 `\n` 接）。
- **流式序列**：所有純量位置（值、清單項、元素物件的值）。合法 JSON 照 JSON；否則單層、元素都是純量（引號內的逗號照解）轉成陣列；巢狀容器、流式鍵值對、空元素、流式物件整段回退原文。
- **型別**：清單元素裡不帶引號的純量認 `~`、`null`、`true`、`false`、數字（同 `restore_leaf`）、合法 JSON、流式序列，其餘字串。
- **元資料**：清單整支與清單外的合法 JSON（含 VWD）都先經 `clean` 剝 `$meta`、`$__META_EXTENSIBLE__$`、`$arrayMeta` 元素；沒有元資料的合法 JSON 葉子保留原文。
- **重複路徑**沿用舊 `insert_initial_tree_node` 語意：分支合併、葉子後者為準、已是葉子的位置不被後到的分支取代。

## 已知限制
- 樹模式桌 GM 回 YAML 狀態區塊寫到同一支清單時，`replace_lists` 把 JSON 葉子整支換成索引分支（行內陣列今天已是如此）〔模型判斷·未裁決〕。
- 清單外的純量照舊存文字、物化時再推斷：帶引號的 `"5"` 會變數字、`HP: ~` 是字串 `~`。
- `#` 註解不處理（照舊當行首記號剝掉、行尾 `#` 留在值裡）；`True`／`NULL` 等大小寫變體當字串；`\n`、`\t` 等其他跳脫留原文；`>` 不以空白接行、`|`／`>` 不保留空行與相對縮排、不加結尾換行；區塊純量沒有續行時，清單項會被略過、清單外的 `鍵: |` 得到空字串。
- YAML 不認的其他部分：`0x1F`、`.inf`、`1_000`、`08`（當字串）、錨點／合併鍵、多文件、多行純量（續行丟掉）、流式物件與巢狀流式容器（原文）。
- `+5`：清單項 `- +5` 會先被剝掉行首 `+` 記號、變成數字 5；具名鍵的值與流式元素裡的 `+5` 留成字串。
- 舊桌已存的空 Branch 重新匯入不會修正（initvar 只補缺不覆寫；發佈前舊桌不相容可不管）。
