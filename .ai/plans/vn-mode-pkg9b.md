# vn-mode 包 9b 方案：卡內美術欄位接進生圖

總綱 [vn-mode.md](vn-mode.md) §6（VN 卡封面與 `art`／`locations` 只進生圖）、§9（立繪、`height_cm`）、§15、§12 拍板 16；研究報告 [vn-card-sunsmell](vn-card-sunsmell.md) §2.3（I 層欄位）、§5 #5–#7、#11；9a 定案 [vn-mode-pkg9.md](vn-mode-pkg9.md)（美術欄位原樣存在 `vn.json` 的 `card.extras` 與 `card.cast[id].extras`）；生圖管線 [包 7](vn-mode-pkg7.md)、[包 3](vn-mode-pkg3.md)。

大案、碰信任邊界輸入（卡作者寫的文字進生圖提示詞、鍵進檔案路徑）：方案與驗收都送 Sol。**2026-11-02 完成**：方案審 2 輪（必改 3＋0，串 01a197a8）、驗收 1 輪 PASS 無必改（串 01a197f5）。核心估約 **750**（§6）。本檔除標〔作者裁決〕者皆〔模型判斷·未裁決〕。

## 1 業界做法與我們的對應

| 業界 | 我們 | 差距 |
|---|---|---|
| 角色一致性：角色設定表（model sheet）＋固定外觀提示（SD 圈的 character tag 串）＋LoRA／IP-Adapter 參考圖 | 卡作者寫英文外觀規格塊 `appearance.spec`，取代公開設定當生圖描述；卡圖或封面當參考圖 | 沒有 LoRA；跨圖一致性靠規格塊＋參考圖＋玩家重骰 |
| 畫風統一：style prompt＋negative prompt＋style reference 圖（Midjourney `--sref`、IP-Adapter style） | `art.style`／`art.negative`／`art.background_rules` 接在每張提示詞；封面當畫風參考圖 | 雲端 CLI 沒有 negative 參數，只能寫成「避免」句 |
| Ren'Py／Naninovel：背景與表情都是宣告過的具名資產，腳本只能引用清單內的鍵；時段變體＝同背景另一張 | 卡內 `locations` 當 `[bg]` 的枚舉、每地點宣告自己的時段鍵；額外表情鍵按角色宣告、清單外退 neutral | 一致；卡外自由地名仍照包 3 雜湊收（不擋 GM 即興） |
| 舞台比例：Ren'Py `zoom`／Naninovel `scale` 依角色設定 | `height_cm` 照比例縮放、最高者滿版 | 一致 |

## 2 定案設計

### 2.1 卡美術欄位改成型別、匯入時驗（取代 9a 原樣保存）

9a 存的是原樣 JSON，只在匯出時寫回；9b 開始讀它進提示詞與路徑，所以改成型別結構、**匯入時**驗證正規化（發佈前不顧舊桌，見記憶「舊桌不相容」），生圖端只讀驗過的值。`CardOrigin.extras`／`CastOrigin.extras` 換成：

```
CardArt { style, background_rules, negative, cover_as_style_ref: bool }      // 卡層級 art
CardLocation { key, name, times: [時段鍵], prompt, scale }                    // ≤20
CastArt { appearance: { spec, notes }, expressions: [{key,label,prompt}] ≤6,
          variants: [{key,label,prompt}] ≤4, height_cm: Option<u16> }
```

外部卡欄位對映（卡格式照報告 §2.3 不變，匯出寫回原名）：`locations[].slug → CardLocation.key`、`cast[].expressions_extra → CastArt.expressions`，其餘同名。

- **單一來源**：卡美術欄位只存在 `vn.json` 的 `card`，匯入後不可編輯；`sprite.json` 不複製表情清單或變體宣告。commands／佇列層每次需要時讀 `vn.json` 一次，把該角色的表情清單（`&[String]`）與宣告傳進 store／queue／提示詞函式；換定稿、重開 app 續生都從同一處取。
- 文字：長度照報告 §2.3 夾斷（spec 600、style 600、background_rules 800、negative 300、地點 prompt 500、scale 200、label 32、各 prompt 300）＋notice；控制字元剝掉；拼進提示詞時以「卡作者提供的描述」標頭包起來；這只是提示詞層的區隔，**不是執行邊界**，不保證模型把它當純文字。實際限制分來源：Codex 生圖以 `-s workspace-write`、app 自己的 `CODEX_HOME` 與 `--ignore-user-config` 跑，工具可寫範圍限工作目錄；agy 生圖帶 `--dangerously-skip-permissions`，模型可執行的工具沒有限制；API（OpenRouter）只回圖、不執行工具。只從本次工作目錄取圖限制的是結果讀取，「只呼叫一次」是提示詞要求。剩餘風險：惡意卡文字在 agy 來源可誘導模型執行工具——與包 7 的 `public_md`、包 3 的 `world.md` 進生圖提示詞是同一條既有曝險，9b 不新增執行面也不收緊；agy 生圖的執行限制另觀察立案（見 §5），不在本包。
- 鍵（表情、變體、地點、時段）：`[a-z0-9_-]{1,24}`，不合格整筆丟＋notice；鍵會進檔名（`face/<表情>.png`、`body/<變體>.png`、`<slug>-<時段>.png`），照 7b 變體鍵做法兩層擋：匯入時驗、組路徑時再驗一次；表情鍵不得與固定五鍵、演出指令（`closeup`／`shake`）撞名；變體鍵不得是 `base`；同角色內重複留第一筆。
- `height_cm`：50–2000 整數，範圍外丟掉。
- 匯出（9a `export.rs`）改從型別寫回同名欄位；卡外桌沒有就不寫。100,000 字元超量時先丟美術欄位的規則不變。

### 2.2 外觀規格與畫風進立繪提示詞

- 定稿：角色有 `appearance.spec` 時，描述段改成「Appearance spec (from the card author): …」＋notes，不再帶 `public_md`（規格塊是給生圖寫的，公開設定混入劇情文字只會干擾）；沒有就照舊。
- 卡有 `art.style` 時，定稿／變體提示詞的「Clean anime visual novel art style」換成卡畫風；`negative` 接成「Avoid: …」句。七分身、正面、透明底等規格塊不讓卡覆蓋（管線要靠它對齊）。
- 表情（裁頭重繪）不加畫風：參考圖本身就是畫風。

### 2.3 額外表情鍵（拍板 16）

- 每角色表情組＝固定五鍵＋該角色卡宣告的鍵（≤6）。臉層生成、`missing_faces`、佇列、狀態事件、立繪分頁表情列、Stage 疊圖全部從「該角色的表情清單」取，不再是全域常數；臉層路徑照舊 `face/<鍵>.png`（鍵已驗）。補生順序：固定四張先、額外鍵後。
- 額外鍵的表情描述用卡的 `prompt`，標籤用卡的 `label`。
- 解析器：對白格的表情若是該說話者宣告的額外鍵就收，否則照舊退 neutral（`VnRoster` 帶每個名單角色的額外鍵）。
- 提示詞：GM 規範與角色線規範的表情句改成「固定五鍵，另可用下列角色專屬表情」（不再寫「只能用」固定清單），後面加「角色專屬表情」清單（只列有宣告的角色），放 system 穩定前綴；角色線只列自己的。

### 2.4 變體宣告

- 卡宣告的變體在匯入時寫進 `sprite.json` 之前不存在（`sprite.json` 要等定稿挑定才有），所以改成：立繪分頁「身體」列把卡宣告但還沒生的變體顯示成空格，有「生成」鈕；生成時鍵用卡的 `key`、描述用卡的 `prompt`、顯示名用 `label`。玩家仍可另外新增。
- **不自動生成**：變體每張要動玩家額度，卡宣告不等於玩家要；表情差分自動補是作者裁決過的管線，變體沒有〔模型判斷·未裁決〕。
- **鍵的保留與分配**：卡宣告的變體鍵是保留鍵。`next_variant_key`（玩家新增時自動配鍵）要避開 `sprite.json` 已有鍵與該角色卡宣告鍵；生成端（`start_variant` 一類）允許「卡已宣告、`sprite.json` 尚未寫入」的鍵，生成完才寫進 `sprite.json` 的變體清單（label 取卡的）；不在 `sprite.json` 也不在卡宣告的鍵照舊拒收。刪除卡宣告變體＝刪圖，空格回到「未生成」。
- 變體注入提示詞改列「卡宣告的變體 ∪ 已生成的變體」：卡宣告的從開桌就在，system 前綴穩定，不因玩家生成而改（順帶減輕包 7b「新增變體斷快取」限制）；GM 用到還沒生的變體＝退路鏈退預設身體。

### 2.5 地點與時段

- `[bg: X | T]` 解析時，X 對卡內地點（`key` 或 `name`，經包 3 同一個 `fold` 比對）就用該地點：背景庫 slug＝`slug_of("card:" + key)`（路徑仍只由雜湊組成）、`backgrounds.json` 顯示名＝卡的 `name`、生圖地點描述＝卡的 `prompt`＋`scale`。對不到的自由地名照包 3。
- 時段：每個地點有自己的**有效時段清單**——卡地點宣告了 `times` 就是那幾個鍵，沒宣告的卡地點與自由地點是固定四鍵。`[bg]` 寫的時段先比對鍵本身，再走包 3 同義詞表把「黃昏」等映到 `dusk`，結果要在**目的地**的清單內才收；不收或沒寫＝沿用同幕目前時段，但只在它也屬於目的地清單時沿用，否則取目的地清單第一項（例：洞穴 `crisis` → 工房沒寫時段＝工房第一個時段，不帶 `crisis`）。解析、整幕讀取補沿用、重生成、參考圖搜尋全部以目的地清單為準。
- `Library::reference`（找同地點其他時段當光線參考）改成搜尋該地點的有效時段清單，不再只搜固定四鍵（例：洞穴先有 `moonlight`，生 `crisis` 時以它為參考改光線）。生圖光線句：固定四鍵照包 3，卡自訂鍵（如 `moonlight`、`crisis`）寫成「Time of day / mood variant: <鍵>」。沒宣告 `times` 的卡地點照固定四鍵。`Backdrop.period` 從 `&'static str` 改成驗過的字串，連動 `BgSlot`、佇列身分、`backgrounds` 指令與 `backend-contracts.ts` 的時段型別；`known_period`（指令收前端傳來的時段）改成以該背景 slug 對應地點的有效時段清單驗，組路徑前再驗一次鍵格式。
- GM 規範：卡桌在 `[bg]` 那句後列出「可用地點：名稱（時段：…）」，要求優先用清單內地點、照寫名稱；清單外仍允許（即興場景）。放 system 穩定前綴。解決 9a 觀察「GM 寫自由地名」。
- 背景提示詞加 `art.background_rules` 與 `negative`；`art.style` 取代 SPEC 的通用畫風句。

### 2.6 封面當畫風參考圖（報告 §5 #11）

參考圖種類改成明確列舉（取代 `has_reference: bool`），每種各有自己的提示句：立繪＝`CardArt`（角色卡圖：取外觀）／`CoverStyle`（封面：只取畫風）；背景＝`SameLocation`（同地點另一時段：鎖構圖只改光線）／`CoverStyle`。

- `art.cover_as_style_ref` 為 true 且有 `vn/cover.png` 時：
  - 定稿：角色沒有卡圖時，封面當參考圖，提示詞說明「只取畫風（線條、上色、光影），不要照抄封面的人物、構圖、背景」。角色有卡圖時仍用卡圖（只收一張參考圖，不改取圖層介面）。
  - 背景：沒有同地點光線參考圖時，封面當畫風參考圖（同樣只取畫風、不畫封面人物）；有同地點參考圖時以構圖一致優先，不帶封面。
  - API 來源照包 3 不帶參考圖。
- 風險：模型可能把封面人物畫進背景。實測項目之一；不行就只用在立繪，背景不帶，記結果。

### 2.7 身高縮放（報告 §5 #6）

- 基準是**名單中有填 `height_cm` 的最高者**（不是同框最高者）：身體層高度＝`height_cm / 基準` × 滿版高度，下緣對齊；每角色比例固定，不因誰進退場而跳動（同 Ren'Py／Naninovel 每角色固定 zoom）。沒填的角色照現行統一比例（滿版）。名單都沒填＝現行行為。
- 臉層跟著身體層同比例（它本來就以身體圖百分比定位）。
- 前端從既有讀取（立繪全讀或 `vn.json` 視圖）帶出每角色 `height_cm`，不另開命令。

### 2.8 分級與生圖被拒（總綱 §15 延伸，不在作者這次列的七項內，可砍）

報告 §5 #12：生圖失敗原因碼是 REFUSED 且卡分級為 teen／adult 時，立繪分頁與背景字卡的失敗提示多一句「這張卡分級為成人／青少年，供應商可能拒絕；可在設定換立繪來源」。退路鏈照舊。

### 2.9 不做

- 主角立繪：第一人稱 VN 慣例主角不上台（9a 定），卡給主角的 `appearance` 照存不用〔模型判斷·未裁決〕。
- 依 `chapters[].locations` 預生背景：9a 已刪此欄。
- 卡內地點以外的背景清單管理介面。

## 3 測試

- 單元：美術欄位驗證正規化（夾斷、壞鍵丟棄、撞名、重複、height 範圍、控制字元）與匯出往返；表情清單合併與解析器收額外鍵（別人的額外鍵不收）；`missing_faces` 含額外鍵且順序固定鍵先；地點比對（key、name、全形／大小寫）、卡時段鍵比對與同義詞映射與沿用；卡地點 slug 與自由地名不撞；換地點時段只沿用目的地清單內的（洞穴 `crisis` → 工房省略時段＝工房第一個時段）；`Library::reference` 找得到卡自訂時段（洞穴 `moonlight` 在、生 `crisis` 以它為參考）；變體鍵保留與分配（卡宣告 `v1` → 玩家新增不占 `v1` → 生成宣告變體，兩者都在）；提示詞組裝（spec 取代公開設定、style 取代通用句、negative 句、封面參考句）；身高比例計算（全填、部分填、都沒填）；變體注入列卡宣告∪已生成。
- 測試通道真生圖（Codex；SunSmell 測試卡 `TestCards/sunsmell-vn-card.json`）：匯入 → 精靈 ③ 誠吾以外角色定稿（看規格塊與畫風是否吃到、封面參考有沒有被照抄）→ ④ 開演 → 額外表情臉層生成並上台（`lak` 的 `tender`）→ 卡地點 `[bg: 拉克的工房 | 黃昏]` 命中卡地點、提示詞用卡 prompt → 同地點卡自訂時段連續兩張（洞穴 `moonlight` → `crisis` 構圖一致）→ 洞穴 `crisis` 換到工房省略時段→ 拉克與老婆婆同框身高差 → 立繪分頁卡宣告變體空格與生成。截圖主線親看。

### 3.1 實測結果（2026-11-02，測試通道，立繪／背景 Codex、GM gpt-6-luna；生圖 23 次含 2 次 REFUSED，GM 2 回合）

- 匯入 SunSmell PNG：美術欄位全數型別化存進 vn.json、無提示。拉克、老婆婆定稿吃到外觀規格（紅虎單肩織帶寬腰布、垂耳白耳尖的兔婆婆）與卡畫風；兩人都無卡圖，封面（燈籠茶壺靜物）當畫風參考，畫面沒有照抄封面物件。拉克第一次定稿 REFUSED，重骰成功。
- 開演後拉克 7 格臉層（固定四＋guarded／guilt／tender）依序補齊、無失敗；`拉克·桑加 (tender)` 上台用 tender 臉層。GM 寫 `林和也 (tender)`（別人的鍵）正確退 neutral。
- 卡地點：開場 `[bg: ferry | afternoon]` 與 GM 寫的 `[bg: 渡輪船艙 | afternoon]`、`[bg: 日嶼碼頭 | dusk]` 都命中卡地點（GM 照「可用地點」寫名稱與時段鍵）；背景照卡 prompt 與尺度出圖（工房巨型工作台與工具）。提示詞全文用臨時測試從實測桌 vn.json 組出核對（AI log 不含提示詞）。
- 注入劇本格（`append_transcript`）：工房黃昏→洞穴 moonlight→洞穴 crisis（以 moonlight 為參考，構圖一致只改光線）→工房省略時段＝`day`（工房清單第一項，以黃昏那張為參考構圖一致）。洞穴 moonlight 與工房黃昏是封面畫風參考，沒有封面人物或物件混進背景，背景照舊帶封面。
- 同框身高：老婆婆約拉克 37%；特寫原本疊身高比例仍很小，改成特寫不套身高比例後放大正常。
- 立繪分頁：額外表情以卡上顯示名列在固定四格後；卡宣告變體「祭典裝」「附身」顯示成空格，生成祭典裝（第一次 REFUSED、重骰成功）後寫進 sprite.json 並照卡 prompt 換裝。

## 4 已知限制

- 身高以名單最高者為基準，小個子單獨上台也很小（SunSmell 老婆婆 130 cm 對拉克 355 cm，約 37%）。基準取卡上全體有填身高者（含不上台的主角）；只縮有立繪的角色，角色卡原圖佔位照舊滿版。
- §2.8 分級提示沒做（方案標可砍；核心已超估）。實測成人卡在 Codex 下拉克定稿與祭典裝各被拒一次（重骰都過），這條提示有實用價值，可另立案。
- 特寫（`closeup`）不套身高比例〔模型判斷·未裁決〕：小個子特寫照常放大。
- 地點字卡照劇本原樣顯示時段（卡自訂鍵是英文，如 `afternoon`、`crisis`）。
- 角色線的格式規範句（全卡共用前綴）不改；該角色自己的專屬表情另段附在變體段後（「除固定五種外另可用」）。
- 卡宣告變體的顯示名匯入時照變體名規則驗（≤24 字、不含 `@`、括號、逗號、冒號、不叫 base），不合格整筆丟；表情顯示名只夾 32 字。
- 封面參考在立繪與背景都不給 API 來源（照包 3 API 不帶參考圖）。
