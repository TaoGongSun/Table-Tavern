## 2 成品樣子

- 手機編卡畫面的角色圖區，按鈕列是「上傳圖｜從圖庫選（N）｜移除」。圖庫是空的就不出現「從圖庫選」。
- 按「從圖庫選」，在按鈕列下面展開縮圖格，新的在前。目前套用的那張標「使用中」。一次載入一頁，還有就出現「再載入 N 張」，跟桌面版生圖窗的圖庫一樣。
- 點一張縮圖，或按 AI 生圖預覽下的「用這張」，或選好要上傳的檔，三條路都先打開裁切窗。裁切窗是 2:3 長方形，可以拖、可以捏或用滑桿縮放，跟桌面版的「裁切角色圖」一樣。
- 裁切窗一打開，採用預設的置中裁切：放得進整張圖的最大 2:3，置中。不是 2:3 的圖，不調整直接按「確定」也會切掉一部分。這點照桌面版。
- 裁切窗按「確定」只放進草稿：角色圖區換成裁好的樣子，下面寫「已選用，按存檔才會套用」。按存檔才寫入；按返回就撤回，會跳離開確認。按「取消」就什麼都不變。
- 生圖後按「丟掉」，或選了沒存就返回，那張圖還在圖庫裡，下次開圖庫撿得回來。
- 返回確認框的「捨棄修改」是紅字紅框，「繼續編輯」維持主要按鈕樣式，預設焦點照舊在「繼續編輯」。
- 名冊的圓形頭像對齊圖的上緣，2:3 的圖不會把臉切掉〔模型判斷·未裁決；常識審查員〕。

## 3 做法

### 3.1 協定：新增 `card.gallery`

照 `card.mine` 一比一做，一種訊框、兩種用法。

- 成員送 `card.gallery { before?: 檔名 }`：列一頁。
- 成員送 `card.gallery { file: 檔名 }`：只取那一張，用給裁切窗的較大預覽。
- 伺服器轉給執行端 `card.gallery { reqId, memberId, cardId, before?, file? }`。
- 執行端回 `card.gallery.result { reqId, ok, items?: [{ file, thumb }], more?: 數字, code? }`。
  - 列頁時 `thumb` 是縮圖，`more` 是後面還沒看過的張數。
  - 單張時 `items` 只有一筆，`thumb` 是較大預覽，不帶 `more`。
- 伺服器回給成員 `ok { items, more }`。
- `card.read.result` 的 `card` 多兩欄：
  - `gallery`：圖庫張數。
  - `galleryFile`：目前套用的圖從哪張圖庫圖來，可以沒有（§3.6）。
  - 伺服器 shape 加 `gallery?:i galleryFile?:s~`。`galleryFile` 要符合 `GALLERY_FILE`。沒報（舊執行端）就當 0 和沒有。

要動的位置：

- `party/server/core/validate.ts`：
  - `MEMBER_FRAMES` 加 `"card.gallery": "before?:s file?:s"`。
  - `EXECUTOR_FRAMES` 加 `"card.gallery.result": "reqId:s ok:b items?:a more?:i code?:s"`。
- `party/server/core/types.ts`：`CardReq.kind` 加 `"gallery"`。
- `party/server/core/cards.ts`：
  - `REQ_TTL.gallery = 30_000`。
  - `CARD_MEMBER["card.gallery"]`：
    - 先跑 `mine(tx, m)`。
    - `before`、`file` 有送就要符合 `GALLERY_FILE`，兩個不能同時送。
    - 限流，見 §3.4。
    - 然後 `forward(..., "gallery", ...)`。
  - `CARD_EXECUTOR["card.gallery.result"]`：
    - 先 `take`。
    - 回覆前用 `seatedOn` 再驗座位，不對就回 `E_STATE_CONFLICT`、不帶內容。
    - 內容要驗：`items` 最多 24 筆，每筆 `file` 符合 `GALLERY_FILE`、`thumb` 符合 `PNG_URL`，`more` 是非負整數。
    - `items` 是空的時 `more` 必須是 0。
    - 驗不過回 `E_INTERNAL`。
- `src-tauri/src/room/link.rs` 的 `on_frame` 加一行 `"card.gallery" => cards::on_gallery(room, p)`。

### 3.2 座位重驗

跟 `card.mine` 一樣三段：

1. 伺服器收到時用 `mine()` 驗：成員有座位、執行端在線。卡 id 由伺服器填成員目前的座位，手機不送 `cardId`。
2. 執行端用 `seated_card(room, memberId, cardId)` 驗：伺服器說的座位相符、卡在桌上、不是舞台卡。不符回 `E_FORBIDDEN`。
3. 結果回到伺服器時再驗一次座位，換座了就丟掉內容。

`settleCards` 對不是 `save` 的請求，換座就作廢、30 秒逾時、執行端斷線判失敗。新的 `gallery` 自動涵蓋，不用另外寫。

存檔帶裁切時，執行端在耗 CPU 的裁切做完、寫入前，在寫入鎖底下再跑一次 `seated_card`（§3.5）。

### 3.3 檔名信任邊界

手機送回的檔名只出現在三個地方，每一處都已經擋住，或這次補上：

- **`before`（翻頁游標）**：伺服器驗 `GALLERY_FILE`。執行端只拿它跟 `list_gallery_image_files` 列出來的名字比大小、切片，不拿去組路徑。
- **`file`（取單張）**：伺服器驗 `GALLERY_FILE`。執行端先列那張卡的圖庫，名字要在清單裡才去讀，不在就回 `E_FORBIDDEN`。這跟既有 `save()` 對 `imageFromGallery` 的檢查同一套，抽成一個小函式 `gallery_file(root, world, card, name)`，兩處共用。
- **`imageFromGallery`（存檔）**：沿用既有檢查，不新增。伺服器驗 `GALLERY_FILE`；執行端存檔時重新列那張卡的圖庫比對，名字不在就回 `E_FORBIDDEN`，檔案已被刪就回 `E_STATE_CONFLICT`。

「只能是剛列出來的」不另外記每位成員列過哪些名字。理由是：凡是在這張卡圖庫裡的名字，坐在這張卡上的人本來就列得到，所以「屬於這張卡、當下還在」就是要守的條件，記清單沒有多擋到任何東西。

### 3.4 回傳大小、翻頁與限流

**大小**

- 實量：生成圖縮到 320px 的 PNG 約 140 KB，base64 後約 187 KB，一則 1000 KiB 只放得下 5 張。縮到 160px 約 38 KB，base64 後約 51 KB。
- 預算算的是**完整序列化訊框的 UTF-8 位元組**：`{"t":"card.gallery.result","p":{…}}` 整則，包含 `reqId`、`more`、每筆的檔名、引號、逗號，上限是 `READ_FRAME_MAX`（1000 KiB）。
- 執行端每加一筆，就把這一筆序列化後的長度加進累計，用上限扣掉固定包裝與 `more` 最大位數的長度來比。送出前再對整則序列化結果檢查一次，跟 `on_read` 的做法一樣。

**列頁**

- 縮圖 160px PNG，一頁最多 12 張（同桌面版 `GALLERY_PAGE_SIZE`）。
- 執行端從 `before` 之後開始，從新到舊一張張看：
  - 解不開的檔、單獨一張就放不進空頁的檔：跳過，不佔頁數，也不算進 `more`。
  - 放得進就加入。
  - 湊滿 12 張就停；或下一張會讓整則超過預算就停，那張留到下一頁。
- `more` 是停下時「還沒看過」的張數；被跳過的檔已經看過，不永久算在裡面。
- 一路看到底都沒有能放的，就回空頁、`more = 0`。所以不會出現「空頁卻說還有下一頁」，伺服器也照 §3.1 擋。
- 下一頁的 `before` 用這頁最後一筆的檔名。被跳過的檔只可能夾在已加入的檔中間，或落在列尾（這時 `more` 已是 0），所以不會重看。
- 按鈕上的「（N）」是原始張數，可能把壞檔也算進去。差幾張不影響操作，不另外處理。

**單張**

- 用既有 `preview()`（320px），給裁切窗用。320px 的來源放在手機寬約 360 的裁切窗裡夠選位置。裁切本身在執行端對原圖做（§3.5），所以成品畫質跟這張預覽無關。
- 單張也要對整則序列化結果做最終大小檢查，放不下就回 `E_TOO_LARGE`。

**CPU**

- 解碼縮圖會吃 CPU，`on_gallery` 整段放進 `tokio::task::spawn_blocking`，不卡住連線迴圈。
- 既有 `on_read` 是同步只解一張，不動它。

**限流**

列頁和取單張分開算，免得剛展開圖庫就點縮圖，或連續翻頁時吃到 `E_RATE_LIMITED`：

- 列頁 `cgl:<成員>`：每 2 秒 3 次。
- 取單張 `cgf:<成員>`：每 2 秒 4 次。

手機端：

- 同一種請求同時只送一件：列頁進行中，「再載入」停用；取單張進行中，再點別張縮圖不送新的。
- 收到 `E_RATE_LIMITED` 時，照 `retryAfterMs` 等到期，自動重送一次，期間畫面顯示載入中。重送再失敗才顯示錯誤。

### 3.5 裁切

**桌面版實際流程**（`src/features/characters/CardEditor.tsx`、`CardImageDialogs.tsx` 的 `CropDialog`，用 react-easy-crop）：

- 角色圖：本機上傳、AI 生圖窗裡點圖庫的圖，兩條都先進 2:3 長方形裁切窗（`aspect={2/3}`、`cropShape="rect"`）。輸出寬度是 min(裁切寬, 1024)，高照比例，PNG，進草稿，按存檔才寫。
- 頭像：另有一顆「製作頭像」鈕，從目前的角色圖再開 1:1 圓形裁切（256×256），存成 `<id>.avatar.png`。換角色圖不會自動換頭像。
- 圖庫的圖要裁：AI 生圖窗的 `onPick` 直接設 `pendingImage` 打開裁切窗。

**手機網頁做得到**：

- react-easy-crop 原生支援觸控，單指拖、雙指捏合縮放都有，本來就是為手機設計的。
- repo 根已依賴 `react-easy-crop@^6.2.3`，party 加同版本即可（gzip 約 10 KB，React 19 相容）。
- 裁切窗另外保留縮放滑桿，跟桌面版一樣，捏不準時用滑桿。
- 預設框：react-easy-crop 在 `zoom = 1`、`objectFit = "contain"`（預設值）時，裁切框是放得進整張圖的最大 2:3，位置置中。手機照這個預設置中裁切，不另設 `initialCroppedAreaPercentages`，跟桌面版一樣；不是 2:3 的圖直接按確定也會切掉一部分。

**三條路都裁 2:3**（照桌面版）：

| 路徑 | 裁切窗的來源 | 送什麼 |
|---|---|---|
| 上傳圖 | 本機原檔 | 手機用 canvas 依裁切框切出來，再交給既有 `toPng` 縮到 2 MiB 以內，走既有 `card_image` 上傳。協定與執行端都不改。 |
| AI 生圖「用這張」 | `image.gen.result` 帶回的 320px 預覽 | `card.save { imageFromGallery, crop }` |
| 從圖庫選 | `card.gallery { file }` 取回的 320px 預覽 | 同上 |

- 圖庫的圖送「檔名＋裁切框」，不送裁好的圖：手機手上只有 320px 預覽，裁好再上傳會把畫質降到 320px。執行端拿原圖裁，畫質跟桌面版一樣。

**裁切框格式**

- `crop: { x, y, w, h }`，用原圖的比例（0–1）。
- 取自 react-easy-crop `onCropComplete` 的第一個參數，百分比除以 100。這樣跟預覽解析度無關。

**伺服器驗**

- 只能跟 `imageFromGallery` 一起出現。
- 四個欄位都要有，都是有限數字。
- 0 ≤ x、y；0 < w、h；x + w ≤ 1.0001、y + h ≤ 1.0001。
- `card.save` 的 shape 多 `crop?:o`。

**執行端驗與做**

帶 `imageFromGallery` 的存檔（有沒有 `crop` 都一樣）整段放進 `tokio::task::spawn_blocking`，包含最後的寫入階段。理由是 `save_image` 會跑兩次 `save_character_png`，裡面的 `check_character_image` 含 PNG 解壓驗證，也不能回到連線執行緒上跑。

1. 驗輸入：再驗一次同樣的範圍。
2. 在寫入鎖外面完成：
   - 先檢查座位，再檢查檔名（`gallery_file`），然後讀原檔。
   - 有 `crop` 就做：解碼、換成像素並夾在原圖範圍內、`crop_imm`、寬超過 1024 就縮到 1024（同桌面版）、編成 PNG、`check_character_image`。
   - 夾完寬或高小於 1 像素就回 `E_TEXT_INVALID`。
3. 拿 `world_write_permit`，在鎖底下：
   - 再跑一次 `seated_card`。
   - 照現行只覆寫送來的欄位、`write_character`、`save_image`，最後寫來源標記（§3.6）。
   - 圖片和來源標記在同一個寫入鎖內更新。
- 回 `card.save.result` 的時間點不變。
- 行為差異：以前存檔是同步處理，一定排在之後的換座前面。現在帶圖庫圖的存檔如果在處理中途換座，寫入前重驗會擋下來，回 `E_FORBIDDEN`，手機草稿保留。只改文字或移除圖的存檔維持同步。
- 沒帶 `crop` 的 `imageFromGallery` 照舊整張套用，舊手機版本照常能用。

**草稿預覽與頭像**

- 草稿預覽：手機用 canvas 依同一個框把 320px 預覽切出來，當角色圖區顯示的草稿圖。這只是給玩家看的。
- 頭像不另做〔模型判斷·未裁決〕：
  - 房間現行做法是換角色圖時，同一張圖也寫進 `<id>.avatar.png`（`save_image`），裁成 2:3 之後照舊。
  - 名冊頭像（`party/src/App.css` 的 `.seat-card img`）加 `object-position: top`，2:3 的圖 cover 成圓形時保住上半部的臉〔模型判斷·未裁決；常識審查員〕。
  - 桌面版的「製作頭像」圓形裁切不搬，列已知限制。要搬的話多一條「頭像上傳／頭像裁切框」，估多 40 行。

### 3.6 手機介面

改 `party/src/features/my-card/CardImage.tsx`，新增 `CardGallery.tsx` 與 `CropSheet.tsx`，放在同一個資料夾。

**圖庫入口**

- 按鈕寫「從圖庫選（N）」，N 來自 `card.read.result` 的 `gallery`，0 張就不出現。
- 懶載入：按「從圖庫選」才送第一頁，不在開編卡時就撈，因為手機流量和限流都划不來。再按一次就收起來。

**標「使用中」**〔模型判斷·未裁決；常識審查員〕

- 執行端存檔走 `imageFromGallery` 時，在 `save_image` 之後寫一個附檔 `<id>.image-from`，內容是那張圖庫圖的檔名。
- 任何其他路徑換掉或刪掉角色圖時，這個附檔一律刪掉：
  - 在 `import::save_character_png`（角色圖那一型）驗證成功之後、實際寫圖之前刪；`delete_character_image` 在刪圖之前刪。這樣桌面版上傳、裁切、玩家上傳都自動清掉；換圖驗證失敗時，舊圖和舊標記都還在。
  - 房間存圖庫圖時，`save_image` 之後才寫，所以留得下來。
- `character_attachments` 加這個附檔，刪卡時一起清。
- `card.read` 讀這個附檔回 `galleryFile`：內容不符 `GALLERY_FILE`，或那張已不在圖庫，就當沒有。
- 圖庫格裡檔名相符的那張標「使用中」。玩家上傳的圖沒有來源，就都不標。

**跟生圖的關係**

- 圖庫顯示跟 `imageGenRoute`、`imageGen` 脫鉤：房主可能在桌面版替這張卡生過圖。
- 生圖成功後，圖庫張數加 1；圖庫已展開就重撈第一頁。
- 按「丟掉」只清掉預覽，圖留在圖庫。

**三條路的操作**

- 點縮圖：取單張預覽，打開裁切窗。按「確定」後 `setDraft({ file, preview, crop })`，同時清掉生圖預覽區的待決狀態，跟上傳圖一樣。被選進草稿的那張加框標示。
- 「用這張」：改成打開裁切窗，確定後才進草稿。
- 上傳：選檔後打開裁切窗（來源是 `URL.createObjectURL(file)`），確定後才轉 PNG、進草稿。

**草稿與裁切窗**

- `ImageDraft`：圖庫那一型加 `crop`；`saveTo` 把它送成 `card.save { imageFromGallery, crop }`。
- 裁切窗：
  - 全螢幕蓋在編卡畫面上，沿用 `.leave-confirm` 的遮罩樣式。
  - 按鈕「取消／確定」置頂；中間是 react-easy-crop；下面是縮放滑桿。
  - Escape 鍵等於取消。

### 3.7 返回確認框的紅字

`CardSheet.tsx` 的「捨棄修改」按鈕把 `className="ghost"` 換成 `className="danger"`，沿用 `App.css` 既有的 `button.danger`（`--danger` 色字與框，亮暗色都有），不新增樣式。

## 4 驗收

### 自動

`npm run verify`、party test＋typecheck、`cargo test`。

**伺服器**

- `card.gallery`：
  - 沒座位回 `E_SEAT_REQUIRED`。
  - `before` 或 `file` 不合檔名規則回錯誤；兩個同時送回 `E_BAD_FRAME`。
  - 列頁與取單張各自限流，互不吃對方的額度。
  - 回覆前換座：不帶內容，回 `E_STATE_CONFLICT`。
  - 結果形狀錯回 `E_INTERNAL`：檔名不合、縮圖不是 PNG data URL、超過 24 筆、空頁卻 `more > 0`。
  - 逾時與斷線會清掉等著的請求。
- `card.read.result`：`galleryFile` 不合檔名規則就拒收。
- `card.save` 的 `crop`：
  - 驗證函式各測一次：缺欄位、非數字、`NaN`、`Infinity`、負值、零寬或零高、剛好在容差邊界（1.0001 收、1.0002 拒），以及沒帶 `imageFromGallery`。
  - 原始訊框另外測：JSON 寫不出 `NaN`，所以用文字裡的 `NaN` 送進 `validateFrame`，確認整則被拒。

**執行端**

- `card.gallery`：
  - 別人座位的卡回 `E_FORBIDDEN`。
  - 只列自己這張卡的圖，新的在前。
  - `before` 會正確翻頁、`more` 數字對。
  - 有壞檔：跳過，不算進 `more`；全是壞檔回空頁、`more = 0`。
  - 超過整則預算會截斷，`more` 把還沒看過的算進去。整則序列化長度一定 ≤ 1000 KiB。
  - `file` 不在圖庫回 `E_FORBIDDEN`。
- 帶 `crop` 存檔：
  - 存下的角色圖尺寸符合裁切框，寬不超過 1024；頭像同一張。
  - 夾完不足一像素回 `E_TEXT_INVALID`。
  - 裁切期間換座：寫入前被擋下，卡沒變。
  - 存完 `card.read` 帶回 `galleryFile`；之後改用上傳換圖或移除圖，`galleryFile` 消失。
  - 桌面版換圖（`save_character_image`）之後，「使用中」標記消失；換圖驗證失敗時，舊標記還在。
  - 圖片和來源標記在同一個寫入鎖內更新。
- 不帶 `crop` 照舊整張套用。

**建置**：實作後確認 `party/package-lock.json` 新增的依賴都合理（react-easy-crop 會連帶裝 normalize-wheel，屬正常），`party` build 產物正常。

### 測試通道實測

本機 Node 殼＋測試通道桌面版開房，瀏覽器當手機。

1. 手機 A 生一張圖，按「丟掉」。
2. 「從圖庫選（N）」出現，展開後看得到剛丟掉那張。

   - 名冊頭像換成裁好的圖，臉在圓框裡（截圖）。

7. 連續快速點「再載入」與縮圖：不出現錯誤訊息。

## 5 已知限制

- 手機不能刪圖庫的圖，要在桌面版刪〔模型判斷·未裁決〕：範圍考量，加上刪除後難復原，先延後。
- 手機不能另外裁圓形頭像，頭像跟角色圖同一張，靠 `object-position: top` 保住臉（§3.5）〔模型判斷·未裁決〕。
- 圖庫是那張卡的，不是那個人的：
  - 坐上這張卡的人看得到之前在這張卡上生過的所有圖，包括房主在桌面版生的。
  - 換人入座同一張卡，新的人仍看得到這張卡以前生的圖。
  - 玩家在自己卡上生的圖，房主在桌面版也看得到、也能刪。
- 按鈕上的圖庫張數含解不開的壞檔，可能比實際列出的多。
- 測試通道只能用滑鼠模擬拖動與滑桿縮放，雙指捏合要真手機驗。

## 6.1 實作差異（主線送驗收）

- **行數**：核心淨增約 520 行（伺服器 45、執行端 Rust 約 200、手機 TS 約 160、CSS 63），測試約 495 行（Rust 312、伺服器 87、手機 63＋27）。比估計 285 多，主要是：
  - Rust 經 rustfmt 拆行。
  - 手機 CSS（縮圖格、使用中標、裁切窗）沒算進估計。
  - 讀卡多帶 `gallery`、`galleryFile`。
- **帶圖庫圖的存檔一律進 blocking 工作**：有沒有 `crop` 都一樣，只改文字或移除圖維持同步（§3.5）。
- **壞訊框**：`card.gallery` 同時帶 `before` 與 `file`、`crop` 沒配 `imageFromGallery`，都回 `E_BAD_FRAME`，跟既有 `removeImage`＋`imageFromGallery` 同一套，手機正常操作送不出這兩種。
- **翻頁游標**：手機用這頁最後一筆的檔名當 `before`。
- **草稿預覽**：手機切到寬 640（`cutPreview`），只給玩家看。
- **i18n**：party 只有繁中、簡中、英文三份實檔，其餘七語系沿用英文；裁切窗標題、套用、取消、縮放、載入更多照抄桌面版用詞。
- **實測中修掉的版面 bug**：`.card-image img` 原本的 120×120 規則會套到裁切窗內的圖，已收窄成 `.card-image > img` 與 `.card-gen-preview img`。

## 6.2 驗收第 1 輪修正

- **Sol 必改（套用後草稿還沒寫好）**：裁切窗在草稿真正寫好之後才關。處理期間套用、取消、Escape 都停用，編卡整區（存檔、返回）也停用，CardImage 透過 `hold` 借用 CardSheet 的 `busy`。補了延遲轉圖的手機測試。
- **來源標記檔名**：`.image-from` 改用跟 `GALLERY_FILE` 同一套規則（`import::gallery_file_name`），不合規的標記當作沒有。
- **釋放資源**：
  - 草稿預覽的 object URL 在換圖、移除、關畫面時釋放。
  - 上傳裁切窗的來源 URL 在關窗時釋放。
  - `cropTo` 與 `toPng` 用完 `ImageBitmap` 就 `close()`。
- **可控時序的換座測試**：測試專用的 `HOLD_BEFORE_WRITE` 停在「裁切做完、寫入前」，只攔指定那張卡。測試在這段換座、確認換座已生效後放行，存檔回 `E_FORBIDDEN`，圖和標記都沒寫。
- **裁切窗框固定、圖蓋滿**〔模型判斷·未裁決；常識審查員〕：窗本身做成 2:3（`aspect-ratio`），react-easy-crop 用 `objectFit="cover"`。框就是整個窗，圖一開始剛好蓋滿框，沒有灰底；預設仍是置中裁切。
- **存檔後的角色圖**〔模型判斷·未裁決；常識審查員〕：存檔後重開編卡會重新讀卡，`card.read` 回的是執行端存下那張的 320px 縮圖（實測 213×320）。上一輪看起來像原圖比例，是因為角色圖區用 120×120 正方形 cover 顯示。已改成 120×180，跟裁切比例一致。
- **名冊圓頭像**〔模型判斷·未裁決；常識審查員〕：
  - 名冊讀的是執行端的 `<id>.avatar.png`，房間存圖時寫的是整張 2:3 角色圖。`seed::avatar` 用 `thumbnail` 等比縮成 64×96 JPEG，沒有置中裁切。
  - 手機 `.seat-card img` 是 44px 圓形 `object-fit: cover` 加 `object-position: top`（實測計算樣式 `50% 0%`），顯示的是圖的上方 2/3。
  - 上一輪截圖看起來臉被切掉，是因為我把裁切框拖到了偏邊的位置，臉落在圓框邊緣。這輪用預設置中裁切重拍，頭部在圓框內。產生頭像的方式不改。

## 8 觀察

- `cards.rs` 的 `save()` 是在 `seated_card` 之前讀圖庫檔；伺服器的 `mine()` 已經擋掉別人的卡，執行端的寫入也還在座位檢查之後，所以不影響結果，只是順序。這次帶 `crop` 的路徑本來就要改成先驗座位再讀檔（§3.5），不帶 `crop` 的路徑共用 `gallery_file` 時一起調。
- 實測時窗格的截圖在非同步更新完成前就拍下，第一次看起來像沒反應；DOM 確認後重拍正常，不是程式問題。
- 桌面版 CastRail 也讀 `<id>.avatar.png`，房間玩家卡的頭像是整張 2:3 圖，桌面那邊的圓頭像同樣可能切到臉。不在本案範圍。
