# settings-overflow-i18n — 設定頁長字串爆版

## 現象（2026-08-22 俄文實測）
- 「連線」分頁的 CLI 列：label（如 `Grok CLI (режим подписки, для продвинутых)`）＋偵測版本＋`Подключено ✓` 徽章＋兩顆按鈕（重新驗證／切換帳號）擠在同一列，最右邊按鈕被切掉，modal 出現水平捲軸。
- 使用者回報「額度」分頁也容易撐爆，尚未逐項確認。
- 觸發語系：俄文最長，德文／西文／葡文次之；中日韓最短不會爆。

## 方向〔作者裁決 2026-10-03〕
不再三選一。ui-redesign 分包 4 已把連線分頁改成可換行的有框列（`src/styles/settings.css` `.transport-option` flex-wrap），俄文 800×600＋最大字級實機過；本案掃一遍，有爆的照同樣換行做法補（`flex-wrap`／`min-width: 0`），不靠加寬 modal。截圖不必給作者，主線確認即可。

## 驗收
- 十語系逐一開設定頁，連線與額度兩個分頁都不出現水平捲軸、按鈕不被切。
- 800×600 預設視窗尺寸、最大字級（xl）下同樣不爆。`tauri.conf.json` 未設 minWidth，比 800 更窄的視窗不在驗收範圍。

## 掃描結果（2026-10-03，test-harness 獨立 root，零 AI 呼叫）
- 條件：視窗 800×600（內寬 800）、字級 xl（18px）＋俄文 l 對照；使用者 config 副本（四家 CLI 皆已連結）＋真實 `prompt-cache.jsonl` 副本；`<details>` 全展開後量。
- 量測：頁面與 modal 內每個元素查 scrollWidth > clientWidth（可捲／裁切）、右緣超出 modal 或父容器、select 選中文字比框寬；注入過寬元素的陽性對照抓得到。
- 每語系 17 個狀態：外觀、連線（API 各模型模式＋四家 CLI 選取共 13）、額度、版本、作者。
- 爆版只有一處：額度分頁明細表，十語系全爆（需 682–749px、可用 611px），根因是 7 欄並排的數字最小寬度，與翻譯長度無關。
- 修法：模型名改成獨占一列的 rowgroup 標題（每模型一個 `<tbody>`），數字六欄排在下一列；不加寬 modal。修後十語系 xl＋俄文 l 全為 0。
- 邊界資料補掃（俄文、德文 xl，800×600）：副本 jsonl 造整列未回報（colSpan=4）、部分回報的命中率註記、超長模型 id（長連字號 id 與 90 字無斷點 id）、ping 列，各 17 狀態全為 0。
- 表頭補 `scope="col"`；VoiceOver 實際導覽未驗〔模型判斷·未裁決〕。
