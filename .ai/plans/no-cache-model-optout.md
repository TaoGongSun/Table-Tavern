# no-cache-model-optout — 零命中的模型不走共線

**狀態：已立案，只有問題與已知數字。設計留給新對話（等 api-shared-lane 包 B 落地後）。**

## 問題

共線（[api-shared-lane](api-shared-lane.md) 包 B）每輪多送約 1,500 tokens 的全角色名單，換取換角色時不必整包重算。對**確定沒有快取**的模型，這筆支出零回收。

實測：`deepseek-v4-pro-0813-free` 27 筆，`cache_reporting` 全部 `reported`、`cached_tokens` 全部 0——它有回報，回報的值就是 0，不是量不到。

各路徑的成本佔比（帳本實測平均輸入）：

| 路徑 | 平均輸入 | 加 1,500 佔比 | 有無快取 |
|---|---|---|---|
| `deepseek-v4-pro-0813-free` | 4,411 | **+34.0%** | 無 |
| api `stealth/ox-alpha` | 7,927 | +18.9% | 有 |
| codex | 21,308 | +7.0% | 有 |
| grok | 68,692 | +2.2% | 有 |

deepseek 輸入最小，佔比因此最大。它是免費模型，代價不是錢而是延遲與 context 佔用。

## 要設計的四件事

1. **N 定多少**——連續幾輪零命中才判定「這個模型沒有快取」。太小會誤判冷啟動，太大等於沒有。
2. **狀態存哪**——per-model 而非 per-table（快取能力是模型屬性）。`prompt-cache.jsonl` 已有足夠原始資料，要另存狀態還是每次回讀。
3. **重置條件**——供應商後來開了快取怎麼恢復。
4. **要不要讓玩家看見**——退回共線是省成本，但也代表換角色會變慢；額度分頁要不要標。

## 邊界

- 相依 api-shared-lane 包 B，不能先做。
- 與「單角色桌把私設留在 system」（api-shared-lane 結論 3）是**不同的分支條件**，勿混為一談：那條看角色數，這條看模型快取能力。
