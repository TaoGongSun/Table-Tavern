## 3 資料

`worlds/<id>/vn/sprites/<角色id>/`：
- `sprite.json`：`{ version: 1, face: {x, y, w, h}（定稿像素座標）, variants: [{ key, label, face: {x, y, w, h} | null }], default: "base", revs: {<格>: n} }`。變體 `face` 非 null＝獨立表情組，框以該變體身體圖座標存、定位以該圖尺寸計算；null＝共用 base 的框與臉層（Sol 必改 3）。`revs` 是每格（`base`、`face/<表情>`、`face-<變體>/<表情>`、`body/<變體>`）的修訂號，重骰、上傳替換、刪除、改框都加一。表情清單不存，固定 `VN_EXPRESSIONS`。載入時驗：框在對應圖片範圍內、變體鍵唯一且保留 `base`，不合格的框退預設框。
- `body/<變體>.png`（定稿＝`body/base.png`）；`face/<表情>.png`（共用表情組，neutral 不存＝定稿本身）；`face-<變體>/<表情>.png`（獨立表情組）；臉層 PNG 尺寸＝臉框、已羽化 alpha。
- `candidates/<時間戳>.png`：定稿候選（精靈 ③ 與立繪分頁重骰用），挑定＝複製成 `body/base.png` 並清空候選以外的舊臉層（換定稿＝表情全部重生）。
- 生成狀態不落檔：佇列由「有定稿但缺哪些臉層」推導，重開 app 自動續生；失敗次數只在記憶體，重開歸零。
- 鍵與檔名：變體鍵限 `[a-z0-9_-]{1,32}`（label 另存顯示名，劇本 `@變體` 比對 label 或 key），表情鍵限 `VN_EXPRESSIONS`；路徑一律由鍵組成，不收外來路徑。

## 4 生圖流程（後端 `vn_sprites/`）

**取圖層（修 §0 問題，新舊路徑共用）**：codex 從 `thread.started` 取 thread_id，讀 `$CODEX_HOME/generated_images/<thread_id>/` 唯一那張（多張取最新、記一行警告），讀完刪該目錄；agy 讀該次對話的 `brain/<id>/` 圖檔，讀完刪；都找不到才退回「回覆抓路徑」，且只收解析實際路徑後落在本次工作子目錄內的圖（Sol 必改 1：現行接受回覆裡任意絕對路徑，會錯抓並行工作的圖）；thread／對話 id 先驗為單一路徑元件，清理也只限本次目錄。回覆的 NO_IMAGE／REFUSED 暗號只在找不到圖時才採信。每家生圖一次一張（agy 並行即 429），每個工作用自己的子工作目錄，不再清整個共用 `cli-workspace`。

**參考圖輸入**：codex `-i <檔>`；agy 把檔放進該工作的子工作目錄並在提示詞寫檔名（補測做法）；API（OpenRouter）在 user 訊息帶 `image_url` data URL——API 路線補測未涵蓋，施工時先打一張確認，不通就該來源標「不支援表情差分」、只能上傳（§9）。

**提示詞**（英文，算核心；全文定稿在補測腳本，施工時搬進 `transport/vn_sprite_prompts.rs`）：都帶「Call the image generation tool exactly once; do not retry, edit, crop, composite or post-process」（補測：codex 不帶時各生 2–3 張、耗時加倍）。
- 定稿：七分身（頭頂到小腿中段、不見腳）、正面直立、雙手自然下垂、中性表情閉嘴、直式、頭上留白、乾淨動漫 VN 畫風、平光；codex＝真透明 PNG；agy／API＝素色淺灰底（寫透明會畫假棋盤格）→ 去背。規格塊不寫左右。角色名＋公開設定（`public_md` 或描述）＋卡圖當參考圖（有的話）。
- 表情：裁頭圖＋「只改表情、不重新取景、同畫布同頭位、透明區維持透明」。表情描述五句固定英文。
- 臉框：codex 唯讀精簡旗標＋`-i`，回一行 JSON `{x0,y0,x1,y1}`（眉上到下巴、兩頰外緣、不含耳與髮）；只認範圍內、面積合理的框，不合格重問一次，再不行用預設框（圖寬 30%、上 8% 處置中）並在立繪分頁提示手調。非 codex 來源的臉框也走它自己的文字模型＋圖片輸入（agy 回 0–1000 相對座標）；不支援圖片輸入的來源用預設框。

**定稿 → 臉框 → 臉層**：
1. 挑定定稿（候選經 `normalize`；非透明來源先去背）。
2. 臉框：視覺框上緣再往上加框高 25%（挑眉不被切），存 `sprite.json`；玩家可在立繪分頁拖拉。
3. 每個表情：以臉框每邊外擴 40% 取正方形裁切（出界部分透明補齊）→ 放大到 1024 送出 → 回來須近正方形（長寬比差 ≤2%，否則算位移）、任意尺寸縮回裁切大小 → 對齊檢查 → 取內層臉框、邊緣羽化 10 px → `face/<表情>.png`。
4. **對齊門檻**（本地、零額度；補測值，未有真位移樣本）：只比裁切內、臉框外那一圈：兩邊都不透明處 RGB 差 >48 的像素 ≤5%，且 ±8 px 平移搜尋最佳位移為 0；環帶有效像素（兩邊都不透明）不足 500 個時改比 alpha 差 ≤12%；不過＝自動重骰一次，再不過標失敗留給玩家重骰。
5. 佇列：每來源一次一張；精靈 ④ 開演後才開始補表情（§6 定稿先挑、差分背景補〔作者裁決 2026-11-01〕）；狀態以 tauri event 推給前端（角色 id、表情、生成中／完成／失敗＋原因碼）。
6. 寫檔不在生成期間持鎖：工作開始時記下身體圖雜湊、所用臉框與目標格修訂號；生成完才拿 `world_write_permit`，寫前一併重驗（角色仍在、三者都沒變），任一變了就丟掉結果（Sol 必改 2：生成中玩家改框或上傳替換，舊工作不得寫回）。改框＝該組臉層全部失效重生。

**變體**：以定稿為參考圖生新身體（玩家填服裝／姿態描述），同樣七分身＋同畫布；生完比「臉框內」與定稿的對齊（同上門檻、改比臉框內）：過＝共用表情組；不過或玩家上傳＝獨立表情組，另跑臉框與四張臉層。

**去背後備**：`ort` 跑 BiRefNet-lite（224 MB，MIT）；權重放 app 設定目錄，首次需要時下載（§9）；下載走官方來源，SHA-256 固定寫在程式裡；下載完與每次載入快取前都驗，驗不過刪檔拒用。只在非透明來源與玩家上傳不透明圖時用。

## 5 前端

- **Stage 疊圖**：每個在場角色＝身體層 `<img>`＋臉層 `<img>` 絕對定位（百分比＝臉框／所用身體圖尺寸），兩層同一個 figure，現有亮暗、closeup、呼吸動畫照套在 figure 上。退路鏈：該變體該表情臉層 → 該變體 neutral（即不疊臉層）→ 預設變體身體＋共用臉層 → 角色卡原圖 → 剪影＋名牌。`stageAt` 多記每位角色目前變體（`@變體` 沿用到下次切換、換地點清場時保留）。
- **`useSprites(worldId)`**：讀各角色 `sprite.json` 與圖（data URL），聽狀態事件重讀單張。
- **精靈 ③**：列出桌上角色（名單角色，不含玩家）；每角色「生成定稿」＝產一張候選，可再骰、挑定；一鍵「全部生成」。全部挑定才能按下一步；可略過（無定稿＝退路鏈用卡圖）。④ 開演時開始背景補表情。
- **立繪分頁**（角色編輯頁新分頁，元件放 `features/vn/SpriteTab.tsx`，CardEditor 只加分頁入口）：定稿＋臉框（拖拉移動、拉角縮放）；表情列五格（疊在定稿上預覽）、身體列每變體一格；每格狀態與「重骰」「上傳替換」「刪除」；「依定稿重生全部表情」「新增變體」；獨立表情組的變體下多一列臉層。只有 VN 桌顯示。
- **可用變體注入提示詞**（總綱 §16）：GM 與角色線規範列出各角色變體 label（`vn_format.rs`）；沒變體的角色不列。

## 8 預算

立案估 800（已乘 1.5）。依上列範圍逐項估核心：取圖層＋參考圖輸入 150、提示詞 60、裁切／門檻／羽化 130、臉框 60、佇列與事件 150、`sprite.json` 與檔案管理＋指令 160、去背 `ort`＋權重下載驗證 150、Stage 疊圖＋退路鏈＋CSS 100、`useSprites` 80、精靈 ③ 120、立繪分頁＋CSS 300、變體注入 40，合計約 **1500**，是立案估的 1.9 倍。

建議拆兩段，本方案一次送審、分段施工與驗收：
- **7a（約 1000）**：取圖層修正、定稿生成與挑選、臉框、臉層佇列、Stage 疊圖與退路鏈、精靈 ③、立繪分頁（定稿＋臉框＋表情列）。完成即可玩到有表情的立繪。階段限制：7a 沒有去背，立繪只開 Codex 來源（agy／API 在 7b 接上去背後才開）。
- **7b（約 500）**：變體與獨立表情組、`@變體` 渲染與提示詞注入、去背後備（agy／API 來源與上傳不透明圖才需要）。
