# statusbar-yaml-list-flatten：狀態區塊 YAML 清單攤平

## 根因
- 流程：GM 回覆（含開場白）→ `transport/response.rs:336` `extract_state_block` 剝出 `<Status_block>`／狀態圍欄／狀態 `<details>` → `:471` 逐塊 `parse_indented_fields` → `StateBlock.fields` → `mechanism/ledger.rs:164` 逐筆 `set_tree_value`（長度 1 進 `state.table`）→ 樹給 GM「目前狀態」（`state_view.rs:134` `render_state_tree`）與狀態欄（`StateBar.tsx`）。
- `response.rs:513-516`：`- ` 只被剝掉、縮排加 2，清單項當成普通鍵。
  - 物件清單 `- 人物:\n    名字: …`：每項路徑都是 `人物列表/人物/名字`，逐項覆蓋只剩最後一筆。
  - 純量清單 `- "1. 接过热茶…"`：沒冒號整行丟掉（`行动选项/选项` 四項全消失）；項目內有 `:`／`：` 時反被拆成怪鍵。
  - 巢狀清單 `- - x` 只剝一層，同上。
- 零 AI 重現（`TestCards/NorthHall-structure.png` 開場白，暫時測試已撤）：`状态栏/人物列表/人物/*` 三人寫三次、樹上只剩周掌柜；`状态栏/行动选项` 只剩 `名字`。
- 同函式另兩個用途：`import/mechanism.rs:340` `[mvu_update]` 規則表（`check:` 底下大量 `- `，靠現行行為被 `check` 過濾）、`:298` `[initvar]`。

## 修法

### 1. 表示法
「索引分支」＝鍵恰為 `0..n-1`（從 0 起、不缺號、至少一項）的分支（`data::is_index_branch`）；年份 2025/2026、樓層 1/2 不算〔主線裁定〕。沿用既有「數字索引分支」：`mechanism/tree.rs:76` `json_to_node` 把陣列存成 `0/1/…` 鍵的 Branch，`StateBar.tsx:170` 已把全數字鍵分支認成清單。物件項 → `清單/0/人物/名字`；純量項 → 葉子 `清單/0`；巢狀 `- - x` → `清單/0/0`。不用清單欄（`kind: list` 多行字串）表示法：那是重構桌規則型別，未重構桌樹上沒有規則。

### 2. 解析（`transport/state_yaml.rs` 清單感知解析，只給 `extract_state_block`；`parse_indented_fields` 原樣留給 `[mvu_update]` 與 `[initvar]`）
- **容器判定**：父鍵值空，下一行是 `- ` 且縮排 ≥ 父鍵所在欄（含同欄，PyYAML 預設）→ 這些 `- ` 行是該鍵的項目。
- **根層孤立項**（沒有容器的 `- `）：照現行剝 `- ` 當具名鍵（`time`／`place`／`present` 照舊正規化）；無冒號照舊略過。
- **字典啟發式**：容器所有項目都是「單一鍵：純量值、無子層、鍵名互不重複」→ 當字典，等同現行具名鍵寫法；有純量項、多鍵物件項、帶子層的項、巢狀或鍵名重複 → 當清單。
- **項目內容**：每個 `- ` 開新索引（0 起），`- ` 後內容當該項第一行，子鍵縮排以鍵所在欄起算。
  - 引號開頭：找與開頭配對的收尾引號，收尾後只剩空白 → 純量（剝引號，`- "{}"`、`- "[]"` 是字串）；收尾後接 `:`／`：` → 鍵（`- "名字": "林远"`）。鍵值帶引號的 `"[]"`、`"{}"` 同樣是字串。
  - 非引號：有 `:`／`：` 是鍵，沒有是純量。
  - 一行只有 `-`、內容在下一行：下一行（縮排更深）當該項第一行。
  - 無冒號的標題項底下（比 `-` 深）有 `- ` 或 `鍵: 值` 行 → 該項文字當標題鍵（等同 `- 林远:`，剝 `**`）：根層落 `林远/体力`、容器內落 `状态栏/0/林远/体力`〔主線裁定〕。
  - 純量項底下只有純續行（無鍵、無 `- `）→ 續行丟掉。
  - 區塊純量（`鍵: |`、`>` 及 `|-`、`>-`、`|+`、`>+`，以及整項 `- |`）：更深的續行去縮排後以換行串成值，不當鍵解析（清單項內外皆同）。整項 `- |`／`- >` 先於標題項判定，續行含冒號或條列也是值。鍵值 `|` 底下沒有續行就當沒寫值，不動既有值。
- **空值**：`鍵: []` → 容器、零項，樹上是空 Branch（鍵保留）；空純量項（`- ""`）與 `- {}` 略過、不佔索引。
- **數字鍵容器**：容器底下的鍵恰為 `0..n-1` 連號（`0:`、`1:` 回寫）也記進 `lists`，整支替換；不連號的數字鍵是具名容器〔主線裁定〕。
- **混合容器**（同層清單項與具名鍵混用）：不當清單、不移除，走現行具名鍵寫法，舊容器資料保留〔主線裁定，依作者裁決「罕見邊際狀況輕防」〕。現有測試 `extract_state_block_collects_nested_yaml_and_skips_plain_list_items` 依此改寫斷言。

### 3. `StateBlock`
- 加 `lists: Vec<Vec<String>>`（清單容器路徑）與 `Default`；既有 struct literal 改 `..Default::default()`。
- 多區塊：各區塊（`<details>`、狀態標籤、圍欄）在擷取處記下原文起點（剝除外殼時記下每段剝除的位置與長度，倒推回原文座標），依起點排序後合併；同一回覆多個狀態區塊寫同一清單路徑，原文最後一塊整份勝出——後塊的清單路徑把前塊在這支底下的欄位、巢狀清單與空清單標記一併作廢；後塊把前塊的清單改報成具名形（兩個 hp → 一個）也一樣。
- 另記 `maps`（具名容器路徑），供清單身分黏著用。

### 4. 套用（`mechanism/ledger.rs`）
- 位置：在 `old_values` 與 `entry = tree.clone()` 之後、寫欄位迴圈之前（`replace_lists`）。
- 清單身分黏著〔主線裁定〕：`maps` 的路徑在樹上現為索引分支時先移除，再照具名鍵寫（兩項同名單鍵的清單下回合剩一項，只留 `名字`、沒有 `0`/`1`）。
- 所有容器（lists、maps）先由祖先往下判定處置，判完才動樹：有略過的祖先就整支略過、有重寫的祖先就跟著重寫。再對要重寫的 `take_node`，清單以 `insert_node` 放空 Branch（`鍵: []` 留空清單），之後寫欄位。
- 變數模式（`base.is_some()`）〔主線裁定〕：只有容器路徑「不存在」「空分支」或「現為索引分支」才移除重寫；葉子（stat_data 陣列投影出的 JSON 文字）或具名分支一律不移除，這支底下的欄位與巢狀容器也不動，這回合真有欄位被略過時記一筆 Ignored（只進帳本、不回饋 GM；空清單略過不記，免得每回合重複），stat_data 陣列與具名物件原封不動。
- 根層容器寫進樹時刪掉 `state.table` 同名鍵；`time`／`place`／`present` 若是純量清單，以「、」串起寫進 table、不進樹；空清單在平欄寫空值（登場偵測不沿用舊名單）。
- `detect_jumps`：本回合 `lists` 容器底下的路徑舊值當作沒有，不報跳動。
- `scoped_block`：`dropped` 納入 `!lists.is_empty()`，清 fields 時一併清 lists；接管桌只有 lists 時也記拒收。`commands/chat.rs:402` 套用條件加上 `lists` 非空。

### 5. 顯示
- GM「目前狀態」（`state_view.rs` `render_state_tree`）：全量桌把索引分支依數字排序印成 `- ` 清單（空的印 `鍵：[]`；純量項含 `:`／`：` 或以引號、`-`、`[` 等開頭就加雙引號；物件項第一個子鍵接在 `- ` 後、其餘對齊它；巢狀 `- - 值`），多行葉子（具名鍵與清單項）一律印成 `鍵：|`（清單裡 `- |`）加縮排續行；與解析器往返一致（空白行與行首縮排除外）。增量桌保留索引鍵但依數字排序，多行葉子照舊。
- `StateBar.tsx`：分支自身是索引分支（鍵恰為 0..n-1，與後端一致）或在索引分支底下就不掛指認下拉，年份鍵照掛；非根層的空分支內容區顯示空值字樣。

### 6. 已存在的桌
發佈前舊桌不相容可不管；實際上下一次狀態區塊會把已攤平的 `人物列表/人物/*` 整支換成新形，不需遷移。

## 已知限制〔模型判斷·未裁決〕
- 未加引號、內含全形 `：` 的純量項仍會被當成鍵（全形冒號寬鬆認鍵是既有行為）。
- 區塊純量收續行時空白行與行首縮排不保留，不分 `|`／`>` 語意。
- 純量項底下的純續行丟掉。
- 變數模式下每回合把同一支陣列鏡像成清單的卡，仍會每回合記一筆 Ignored（只進帳本、不回饋 GM）。
- 引號內的跳脫 `\"` 未處理。
- 空純量項、`- {}` 不佔索引。
- 行內清單 `[a, b]` 仍存成葉子字串。
- 同回合 YAML 重排清單＋JSONPatch 索引寫同一清單時可能落錯項（非接管增量桌，罕見）。
- 變數模式下原本不存在的清單容器寫進 stat_data 是 `{"0":…}` 物件而非陣列，`[]` 變 `{}`（不毀損既有資料）。
- 全量桌空分支一律印成 `鍵：[]`（具名空分支也是），GM 回寫後會成空清單。
- 全量桌多行葉子改印區塊純量，行首縮排與空白行在 GM 回寫後不保留。
- 清單項純量同時含 `"` 與 `'` 又需加引號時原樣印出，讀回可能被當鍵。
- 清單以外的具名鍵消失時仍沿用現行「不刪舊鍵」行為；混合容器同此。
