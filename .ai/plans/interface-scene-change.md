# 介面桌換幕：前情提要進正文槽、面板與狀態樹原樣續存

本檔存放 [interface-scene-change](../handoffs/interface-scene-change.md) 的規格細節，由交接檔連回。2026-08-13 立案；2026-08-14 Sol 第 1 輪覆核併入；2026-10-06 兩項假設實測完成、分包重定。

## 目的（2026-08-13 使用者定調）

機制複雜、輸出長的介面卡（毛絨卡 Transfur 型）幾輪就把 context 撐爆，沒有換幕配套就不敢長玩。目標行為：換幕後介面照常運作，【前情提要】顯示在介面呈現故事的位置（正文槽），其餘面板完整保留、數值不歸零，後續回合照舊走 patch 契約。

## 現況事實（2026-08-13 盤點，2026-10-06 實測確認）

- 換幕（`commands/scene.rs` `advance_scene`）＝把本幕 transcript 摘要成【前情提要】，`data/scene/lifecycle.rs` `begin_next_scene` 寫成新幕第一則 Narration 事件，**已帶 `marker: scene_summary`**（設計第 1 點要的 origin 標記現成可用，不必新增欄位）。
- 狀態樹本地權威在 `state.json`（`world.state`），換幕不動它；GM 每輪系統提示注入現值，天生跨幕存活。
- 三條補救路皆有守門：`revert_scene`／`regenerate_scene_summary` 要求該幕只有前情提要一則；`revert_scene`、`fork_scene` 都把 `state.state` 設成目標幕最後一則事件快照——設計第 3 點的分岔語意現行已是如此。
- 殼選路在 `src/features/card-interface/card-shell-route.ts` `floorMessage`：原文能讓卡 regex 畫出殼就用原文（direct-first），否則用該樓快照填骨架、正文槽填 `eventDisplayText`（前情提要＝「【前情提要】」標頭＋本文）。正文槽契約是原樣填、不做格式轉換（`refactor-shell.ts`）。

## 實測（2026-10-06，測試通道，西幻卡現場重構）

做法：測試包新桌匯入 `TestCards/WestFantsy.png` 成世界書 → 重構選「保留原卡玩法」（Sonnet，盤點＋展開）→ GM 檔切 Haiku 玩 2 回合 → 換幕 → 重寫提要 → 退回前幕 → 再換幕 → 續玩 2 回合。每步比對 `state.json` 樹雜湊、各事件快照雜湊，介面 iframe 的 srcdoc 落檔後在瀏覽器渲染截圖（測試通道 `shot` 拍不到 iframe 內容，見交接檔）。AI 共 11 次（Sonnet 4 次重構、Haiku 7 次）。

- **假設 1 成立**：換幕前後檯面樹雜湊相同，十棵子樹逐一相同；前情提要事件被補上同一份快照。
- **假設 2 成立**：前情提要落在「當前視角」正文槽；換幕前後兩份介面 HTML 逐行比對只差正文槽與聊天紀錄，地圖、時間 9:30、地點、推薦行動原值不動。西幻卡 regex 沒有劫持摘要（摘要不含 XML）。
- **案例 A 已過**：換幕當下重寫提要（樹不變）、退回前幕（回第 1 幕，樹＝前幕最後快照）都正常。
- **案例 B 已過**：再換幕後續玩 2 回合，patch 照常（CharSheet、CurrentView、時間 9:30→10:00、推薦行動跟動），面板未歸零。
- **新發現：正文槽裡的摘要是 Markdown 原文**。摘要提示詞（`transport/turns.rs` `summary_messages`）要求條列，GM 回 `**地點與時間**`、`- …`、開頭 `—`／`---` 分隔線；聊天欄會渲染 Markdown，正文槽照原樣填，`**` 直接露出（條列 `- ` 讀起來尚可）。處置定案見設計第 1 點。
- 輸出量（字元，text／含 patch 的 raw）：換幕前兩回合 453／802、713／1173；換幕後兩回合 569／1226、1060／1901；摘要 464～564。Haiku 回合 patch 條數 2～3。省 context 的實際效益要長局才看得出，留給包 3 端對端記錄。
- 測試觀察：換幕後第一個玩家句沒進逐字稿、GM 照推進回覆；疑為換幕後重新進桌時 `fill` 搶在輸入框重掛前，屬測試時序而非 app 行為〔模型判斷·未裁決〕，包 3 端對端時等輸入框就緒再送並複查。

## 包 2／3 實測（2026-10-06，同一張測試桌續用，Haiku 6 次）

- 介面工具列「換幕」連點三下：只派送一次摘要、只多一幕（之後按鈕停用）。
- 換幕後檯面樹不變；正文槽是前情提要、佔位字元零殘留；與換幕前同樹的頁面逐行比對，只差正文槽與聊天紀錄，時間「上午10點」不變。
- 重寫提要（樹不變）、退回前幕（樹＝前幕最後快照）、再換幕後續玩兩回合（等輸入框就緒再送，第一句確實落逐字稿；patch 照常，時間 10:00→11:00→正午12點、CharSheet／CurrentView／LocalSystem 跟動）、從第 1 幕分岔（樹＝來源幕最後快照，頁面與換幕前第 1 幕逐位元相同）都過。
- 實測抓到並修掉：重進桌一律收起卡片介面，所以從介面換幕後介面消失；改成介面上換幕成功就重新打開（`advanceScene` 回傳是否換成），重測換幕後介面與 iframe 都在。
- 接管桌摘要加禁標記後，Haiku 三份摘要一份沒有 `**`、兩份仍有 `**` 與條列——禁標記句不等於處理 Markdown，另由正文槽副本處理（設計第 1 點）。
- 「重寫提要後退回前幕第一下沒反應」（前兩輪實測各出現一次）：原因未明、最新包未重現（外部每秒輪詢、補救鈕重新可按就按一次，重測兩次都首擊即退回）。單元測試另證：重進桌卡住時停用、連按不派送、解鎖後首擊有效；chat 不忙但桌級鎖持有時同樣停用。
- Markdown 處置（乙）實測：介面換幕一次（Haiku 1 次）這份摘要剛好沒有 `**`，渲染照常；另把測試桌那則摘要換成帶 `**`、`—`／`---` 行、`3*4`、行內 `---` 的版本重進桌：正文槽強調與分隔線拿掉、19 行條列保留、算式與行內 `---` 不動、時間面板原值，儲存原文不變。
- native 核對（介面換幕後真視窗可點可用）測試通道做不到，排實測佇列梯 2 第 20 項。

## 設計（含 Sol 補強）

1. **摘要防 regex 劫持＝雙層**（2026-10-06 Sol 分包審查第 1 輪補強）：
   - 主層（渲染，只在有重構骨架的接管桌）：`scene_summary` 樓**不走 direct-first**；填骨架時正文槽先放佔位（英數字＋這次選路才產生、確認不出現在骨架／逐字稿／狀態樹的亂數＋樓號），選殼的 regex 套用與圍欄／頁面抽取都只看到佔位，抽完一次掃描換回顯示文字（換進去的本文不再被替換；`<`、`>` 轉全形）。選中的殼若佔位已被卡腳本改掉，這一樓不出殼、改試較舊的樓，都沒有就不顯示介面，不交付漏正文的殼（Sol 驗收第 1 輪）。交給卡片讀訊息墊片的那一樓同樣是換回後的文字。只跳過 direct-first 不夠：骨架填值後整份文字仍經 `findShell`→`applyScripts`→`extractShell`，摘要含 `</UI>` 會讓殼提前收尾、含三個反引號會讓 HTML 圍欄提前結束，兩案後方面板都消失（Sol 以測試卡 `<UI>…</UI>` 重現）。
   - 正文槽 Markdown〔作者裁決 2026-10-06〕：只在正文槽那份前情提要副本拿掉成對強調（`**…**`、`__…__`）與獨立成行的分隔線（同一字元三個以上的 `-`／`*`／`_`，或整行 `—`），條列保留；單獨的 `*`、算式、行內 `---`、沒收尾的 `**` 不動。這是「正文槽原樣填」契約唯一的例外，只限 `scene_summary`；儲存原文、聊天欄與一般回合正文不動。
   - 缺快照：摘要樓沒有 `state.tree` 時用目前檯面樹填骨架（摘要在幕首，檯面樹就是它那一刻的值）；連檯面樹都沒給時，這一樓不參與選殼（只當聊天樓的顯示文字），絕不拿摘要原文去選殼。
   - 第二層（提示詞）：接管桌判定沿用「非 characters＋非空重構骨架」（與 `gm_turn_format`、`begin_next_scene` 同一依據，抽成共用判定），`advance_scene` 與 `regenerate_scene_summary` 兩入口都套；接管桌摘要指示多一句「不得輸出 XML／HTML／角括號標記與程式碼圍欄」。非接管桌 `summary_messages` 以既有 scaffold baseline 驗逐位元不變；接管桌摘要的快取前綴會變，第一次換幕需重建。
2. **換幕入口**：覆蓋層工具列（[CardInterfaceOverlay.tsx](../../src/features/card-interface/CardInterfaceOverlay.tsx)）是宿主 React 元件，關閉鈕旁直接加「換幕」鈕；不需替卡內 HTML 加 postMessage 橋。
3. **補救路語意明訂**：退回前幕＝樹還原成前幕最後快照（現行已如此）；重寫提要＝只在幕首一則時可用（現行守門）；**分岔＝狀態樹回到來源幕最後快照**，不保留分岔前的現值——接管桌逐條驗。

## 驗收（Sol 修正：拆兩條獨立案例，原稿「續玩後退回／重寫」會被守門擋下）

- **案例 A（換幕當下）**：西幻接管桌玩數回合→換幕→介面開著、前情提要在正文槽、五分頁與地圖原值→立即各驗一次「重寫提要」「退回前幕」，介面照常、樹正確還原。
- **案例 B（換幕後續玩）**：換幕→續玩兩回合，patch 契約正常、面板跟動。
- 每項驗收同時比對 `state.json` 與畫面，不能只看視覺。
- 同流程在 Transfur（等該型過接管後）；換幕前後每輪輸出量記錄（省 context 是本案存在理由，要有數字）。
