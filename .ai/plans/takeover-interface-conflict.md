# takeover-interface-conflict：佔位容器讓位給定義容器

## 根因（2026-10-11 測試通道＋sonnet 重構 RPGImmortal，攔 IPC 拿到兩條展開產物）

- 判定在 [refactor-review.ts](../../src/features/refactor/refactor-review.ts) `mergeRefactorInterfaces`：同路徑值／規則不同、葉子撞分支、骨架佔位對不到，任一成立整組介面不套。
- 「格式增强」實為外框（只規定 maintext／BGM／Status_block 排法），但 `<BGM>xxx.mp3</BGM>` 有字，`frame.rs` 不當外框候選、照一般介面展開（BGM 是真欄位，展開本身合理）。模型把 `<Status_block>${必须输出行动选项}</Status_block>` 這句佔位說明當欄位，自長葉子 `行動選項`，撞「美化状态栏」定義的分支 `行動選項.判定…`→整組丟。
- 模型寫成簡體 `行动选项` 時名字不撞、介面套上，但骨架有兩個 `<Status_block>`、順序變狀態欄→正文→BGM、guide 叫 GM 多報一份。

## 拍板做法（三方審查，主線裁決）

只做「佔位容器讓位」；其餘衝突維持整組不套〔模型判斷·未裁決，依作者「重構不保證成功、玩家自選模型重試」〕。實作在 [refactor-slot.ts](../../src/features/refactor/refactor-slot.ts)，`mergeRefactorInterfaces` 排序後先跑它。

1. 判定看來源條目原文：頂層、不帶屬性的 `<Tag>…</Tag>`（與 frame.rs 同一套掃法）去掉 `${…}`／`{{…}}` 後只剩空白＝佔位容器；同一標籤有一處含固定文字就算定義。呼叫端用 `read_worldbook` 的條目算 uid→角色傳進去（`assembleRefactorOutcome` 同樣帶）；沒傳就是舊合併。
2. 某標籤的定義方＝原文定義、骨架也有該頂層容器且含固定文字的第一條候選；其他原文只佔位的候選，骨架裡同名頂層容器在「去掉佔位後固定文字最多一個非空行、不同狀態路徑最多一個」時才算佔位容器（容許模型自編的 `行动选项：{{行动选项}}`），否則維持舊行為（輕防來源掃描盲點）。容器角色只算介面候選用到的來源條目。
3. 合併前剪掉佔位方「只出現在佔位容器內」的路徑（`classifyPlaceholder==="path"`）、對應規則與 guide 行，清空的父節點一併刪；第一個佔位容器換成定義容器原文、其餘拿掉，定義方骨架移除該容器。之後照現行合併與佔位驗證，任一步失敗＝整組不套。
4. 佔位容器含正文槽而定義容器沒有就不換；正文槽以佔位符解析判定（容許 `{{ 本回合.正文 }}`）。
5. guide 刪行：去掉開頭空白、`-`、`*`、反引號後，以被剪的完整路徑（可帶收尾 `*`／反引號）緊接「：」或「:」開頭才考慮刪；同一行還以「路徑：」提到全部候選最後保留的任一路徑（扣掉本條自己剪掉的）就整行留著。
6. 拿掉容器後只收該接縫的空行（最多留一個空行），骨架其他地方的空行原樣。

## 已知限制〔模型判斷·未裁決〕
- 佔位容器裡若其實是真欄位（另一條要求在該容器加 `${x}`）會被當外框剪掉。
- guide 漏刪時，GM 的新增指令可能把剪掉的路徑重新長回狀態樹（不只是被拒）。
- 只認不帶屬性的標籤；`<instruction name=…>` 這類帶屬性的不算容器、也不擋頂層判定。來源端容器被不帶屬性的外層（如 `<format>…</format>`）包住、說明文字又有空的同名容器時，會被誤判成佔位方：骨架那個容器多行或多欄位就被輕防擋下（維持舊行為：整組不套或兩個容器）；只有一行一欄位的真狀態欄仍會被錯當佔位讓位、欄位剪掉。
- 保留路徑恰為被剪標題後綴時（剪 `舊-HP`、保留 `HP`），`- 舊-HP：…` 這行不會被刪。
- 反方向：模型把真佔位拆成多行或多欄位時，輕防不讓位、退回舊行為（修法不生效、不錯套）。
- 原文只放 `${背包清單}` 的真欄位、且骨架只有一行一欄位時，會被當佔位剪掉。
- guide 刪掉的行之後若有接續說明行（縮排、不帶路徑），接續行留著。
