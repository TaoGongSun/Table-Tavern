# 桌子太長撞到指令長度上限：先修 Windows、上限前提醒換幕

## Summary

CLI 通道把提示放進命令列參數，桌子夠長就撞作業系統的指令長度上限，那一輪整個失敗。各通道現況（`src-tauri/src/cli/request.rs`）：codex 走 stdin 不受影響；claude 的 `--system-prompt`、grok 的 system／prompt、agy 的 `-p` 整包都在參數裡。

- macOS 上限約 1MB；2026-08-22 帳本已有一桌約 700KB。
- Windows 單行指令上限約 32,767 字元，經 `.cmd` 包裝更只有約 8,191，中文卡加世界書一開桌就可能超過〔模型判斷·未裁決，未實測〕。

公開前必做〔作者裁決 2026-10-04〕。

## 範圍

1. 實測三個作業系統下 claude／grok／agy 撞上限的門檻與錯誤表現（Windows 用 CI 或 Windows 機）。
2. 撞得到就改傳遞方式（stdin 或暫存檔），不能只靠提示補救。
3. **上限前就提醒換幕**：換幕本身也要送 AI 產前情提要，真的撞上限時連換幕都做不了，所以必須在還送得出去時就提醒「不換幕就沒辦法繼續玩」。門檻要把換幕那次呼叫的長度算進去。〔作者裁決 2026-10-04〕改走 stdin 後指令上限消失，同一套提醒改看模型 context window。
4. 真的撞上時的錯誤走 `api_error_actionable`／`explain_ai_error` 既有的人話錯誤路線，不新增機制。
