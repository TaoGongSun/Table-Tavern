# vn-player-art-style — VN 立繪與背景讓玩家填畫風，被拒絕時講清楚

案別：中案（立案估核心 150–220 行，十語系文案另計）。玩家文字會進有工具權限的 CLI 提示詞，屬信任邊界輸入，方案與驗收都送審。

## Summary
玩家目前沒有地方指定畫風：只有匯入的 VN 卡作者能帶畫風與避免項（`data/vn_art.rs` 的 `CardArt`，匯入後不可改）。加一個選填的畫風輸入框，並把生圖「被模型拒絕」跟一般失敗分開處理。

## 拍板〔作者裁決 2026-11-14〕
- 位置：「美術與音樂」面板、立繪來源選單旁邊；開桌精靈選來源那一步也露出。一個「畫風」欄，立繪與背景共用；「避免」欄收合當進階。
- 優先序：玩家有填就蓋過卡作者的畫風，沒填照舊。
- 改了只影響之後生成的圖；已生好的不自動重生，只提示可以重新生成。
- 範例文字用描述句，不放畫家名。
- 被拒絕：app 不當審查員、不做畫家或 NSFW 黑名單，由各家模型決定；app 要明確顯示「這家模型拒絕了這個請求」，不自動重試、不偷偷拿掉玩家文字再送；給三個選擇：改畫風文字、這次不帶我的畫風重試、換來源。訊息不一口咬定是玩家的文字（也可能是角色設定）。
- 玩家文字加長度上限，套用跟卡作者文字相同的「只當畫面描述」標頭。
- 多人房間生圖只走 API 不變；畫風欄只有房主能填。

## 已知線索
- 卡作者畫風已接進立繪定稿與背景的提示詞（`transport/vn_sprite_prompts.rs` 的 `card_style`、`transport/vn_background_prompts.rs`）；表情改圖不接畫風（參考圖就是畫風）。
- 立繪流程目前沒有「被拒絕」這個狀態；房間建角圖有 `E_GEN_REFUSED`（`room/cards.rs`）可參考。各家 CLI 被拒時實際回什麼沒查。
- 模型默默忽略畫家名的情況偵測不到，當正常結果。
