樣本驗證（實卡 PNG 拆解，定出光譜兩端）：

## 第一項：匯入補強（小，約一天）
現況：`src-tauri/src/import.rs` 匯入只讀五個標準欄位＋character_book，腳本類內容無聲略過，原始檔案已原樣留存在卡片旁——行為正確，缺告知；alternate_greetings（備用開場白，樣本卡帶 3 條）目前丟棄。
要做：
- 匯入時偵測腳本痕跡：卡片 JSON 的 `data.extensions` 有內容，或任一文字欄位含 `<script`／`<%`。規則保持粗略，抓大放小，勿窮舉。
- `import_character` 回傳多一個旗標（動回傳型別＋`lib.rs` 指令），前端匯入完成時提示：「這張卡帶 SillyTavern 專用腳本，已只讀入人設文字；原始檔保留在卡片旁。」世界書匯入（`data.rs` `import_worldbook`）同規則順手蓋到。旗標用可並存的偵測結構（勿單一布林）：[ttrpg-rules-system](ttrpg-rules-system.md) 之後要在同一掛點加骰子記號偵測。
- alternate_greetings 保留：併入卡片私有筆記成「備用開場白」段（實作挑最省寫法，底線：內容不丟失）。
- 世界書卡誤匯改道：角色卡匯入時粗判「書厚身薄」——character_book 條目 ≥3 且 description＋personality＋scenario 合計字數極低（門檻實作抓；兩張樣本卡本體皆近空）→ 提示「這張卡的內容主要是世界書，要改用世界書匯入嗎？」並附一鍵改道（沿既有世界書匯入流程，含選世界）；玩家仍可照匯成角色卡。緣由：世界書匯入按鈕不顯眼，誤匯機率高。反向誤匯少見，抓大放小。
- 提示字串 ×10 語系（`src/i18n/*.ts`，過 `check:i18n`）。
驗收：帶腳本測卡匯入跳提示、素卡不跳；備用開場白匯入後在卡片內找得到；兩張樣本卡走角色卡匯入跳改道提示；cargo test 新增四例（`extensions` 有料／欄位含 `<script`／alternate_greetings 保留／書厚身薄粗判）全綠。

## 第二項：ST 巨集替換（小，約半天）
現況：`{{user}}`、`{{char}}` 等 ST 巨集前後端皆無替換，原文送模型也原文上畫面——模型輕則出戲、重則照唸。
要做：
- 第一版只做兩個：`{{user}}`→當桌玩家角色名（`assemble_*` 已有 player 卡；缺席時用 i18n「玩家」字串）、`{{char}}`→該卡角色名。大小寫不敏感（樣本有 `{{USER}}` 寫法）。
- 替換點：後端組提示詞處（`src-tauri/src/transport.rs`）統一做；前端顯示開場白與卡片文字時同規則。
- 其餘巨集（`{{random}}`、`{{roll}}`、`{{getvar}}` 等）原樣保留——樣本用量極低，需求再起再加。
驗收：樣本卡的 `{{user}}` 在提示詞與畫面都變玩家名；cargo test 蓋替換（含大小寫）。

## 第三項：訊息 Markdown 渲染（中，約一天）
現況：三個顯示點（`src/App.tsx` 角色對話、旁白、串流氣泡）都是 `<span className="text">` 純文字＋pre-wrap。多數模型本來就輸出 `*動作*` 這類 ST 慣例記號，目前有寶沒顯示。
要做：
- 新增依賴 `marked`＋`DOMPurify`，一個渲染元件替換三個顯示點。選這組的理由：消毒器自寫太險，用經千錘百鍊的標準組合。
- 單行換行維持換行（marked `breaks: true`），貼齊現在 pre-wrap 的閱讀習慣。
- DOMPurify 明列 ALLOWED_TAGS 白名單：只放行 markdown 產物（em、strong、code、pre、blockquote、ul、ol、li、p、br、hr、h1–h6）；第一版連 `a` 都擋——聊天訊息裡的連結沒有使用情境，少一個攻擊面。禁 script、iframe、style 與所有事件屬性。
- 串流簡化：生成中維持純文字，該則完成才轉渲染，避免半截語法閃爍。
- transcript 存檔格式不動（存原文），匯出、收回上一句、換幕摘要皆無感；渲染是純顯示層。
- CSS：斜體、粗體、引用、清單、行內 code 在氣泡與旁白的樣式（故事文字維持 serif，token 規則見 ui-overhaul）。
驗收：`*動作*` 顯示為斜體；貼入 `<script>alert(1)</script>` 的訊息以文字顯示、不執行（手動驗＋消毒單元測試）；npm build 綠；長對話捲動無感差。

## 第四項：GM 狀態欄（大，分兩期；第一期 2–3 天）
概念來源＝MVU：由 GM 維護結構化狀態、每回合可見，取代卡片腳本。部件：
1. 存檔：狀態結構 `TableState { table, characters }`（第一期只用桌級 `table`；`characters` 佔位給第二期與跑團規則系統的每角色數值紙，免日後遷移）。目前值存進 `WorldState`（world.json）當快取，權威來源是逐則事件快照（第 7 點）——不另立狀態檔，省一套檔案 IO 與指令。
2. GM 輸出協定（2026-08-02 拍板）：旁白尾端附 ```state 圍欄，內容鍵值行——「欄名：值」一行一欄，壞一行丟一行、其他欄照收（選鍵值不選 JSON：半截 JSON 整塊報廢，容錯差）。後端解析後更新狀態、從顯示文字剝除。基礎三欄的鍵固定英文（`time`／`place`／`present`，值用玩家語言），解析時認在地化別名（時間／地點／在場人物等）折回同一鍵——存檔不綁介面語言，換語系不會對不上。合併不取代：模型漏報的欄位沿用舊值。欄位命名預留角色命名空間（桌級與角色級走同一條協定）。容錯是核心：格式壞＝整塊忽略、沿用舊狀態，遊戲照常，絕無報錯中斷——使用者可接任意模型，紀律不可假設。
3. 卡片自訂格式走同一條管線：剝除規則除自家格式外，認常見包裹——```fenced、`<details><summary>状态栏</summary>`（兽人的洞穴型）、`<status>`／`<UpdateVariable>` 類 XML 標籤（根源重塑型）；認得的剝除並盡量畫進面板，認不出原樣顯示。全量快照型第一期吃；增量 patch 型（MVU JSON Patch）第一期只剝除、面板顯示原文，數值解析歸第二期。
4. 餵回提示詞：`assemble_gm_messages`（`src-tauri/src/transport.rs`）插入「## 目前狀態」；角色上下文只給公開欄位，沿用世界書可見範圍的隔離設計。匯入世界書條目預設 visibility=GM（`data.rs` `visibility_from_value` 現行 fallback），狀態指令天然只餵旁白，免五個角色各報一張表。
5. UI（2026-08-02 拍板）：位置＝主欄標題列（換幕／匯出那排）下方、訊息流最上面，捲動時黏頂。預設收起成一行摘要「時間值 ｜ 地點值 ｜ 在場：人名」，展開成一欄一列（欄名＋值），值點一下就地變輸入框可改（互動同改桌名），收合狀態記 localStorage（同桌列表）。掛上面板的桌基礎三欄都有、沒值顯示破折號；卡片自訂欄偵測到才追加。沒選左欄（離劇情遠、左欄已擠）與每回合插一則訊息（洗版、回捲全是過期狀態）。
6. 狀態列跟著匯入內容走（2026-08-03 拍板）：世界設定、世界書條目、角色卡任一處出現狀態列輸出格式（`状态栏`／`狀態欄`／`status bar`／`<status…>`／`<UpdateVariable>`／```` ```state ````）才掛面板，其餘桌完全不顯示也打不開——不問開關，切桌自動判定。純跑團桌不需要狀態列，掛著一排破折號是雜訊。
7. 與「收回上一句」整合（2026-08-02 拍板）：逐則快照藏在旁白事件裡——事件自帶當回合狀態，pop_transcript 收回即自動回滾，零同步程式；每桌狀態檔只當「目前值」快取（結構仍照第 1 點桌級＋角色區）。玩家手動改欄位＝補一則隱形狀態事件，同樣吃得到收回。
8. 字串 ×10 語系。
風險：ST 卡靠條目壓底（after_char＋高 insertion_order）維持服從，本產品世界書全進 system 段——第一期用樣本卡實測服從度，不夠再議注入位置。
第一期範圍：固定欄位——時間、地點、在場人物。換幕摘要（`summary_messages`）本來就要 GM 整理這三樣，等於把「每幕結算一次」升級成「每回合都在檯面上」；換幕時新場景以狀態為種子。
第二期：開放自訂數值欄位（好感度、金錢等，作者在世界設定裡宣告）＋增量 patch 型數值解析，即 MVU 完全體。等第一期驗收後再細部拍板。跑團規則系統已拍板成獨立任務（[ttrpg-rules-system](ttrpg-rules-system.md)，較晚做）；邊界：本任務管容器（欄位 schema、輸出協定、面板角色分頁、快照回滾），規則任務管內容（卡上初始紙、開桌種入、骰子、注入帳）。二期做欄位可見性時預留「角色本人可見自己角色區的公開欄位」。
驗收（第一期）：GM 回合後狀態欄跟著劇情變；手動改欄位、下一回合 GM 接受；收回上一句時狀態同步倒回；模型故意輸出壞格式時遊戲照常；「兽人的洞穴」實測——`<details>` 狀態區塊從對話剝除、面板顯示天數／環境／在場角色。cargo test 蓋解析與回滾。

## 第五項：世界書條目↔角色卡互轉（小，半天～一天）
現況：世界書卡匯入後 NPC 檔案全躺在條目裡（樣本卡 2 有七個 NPC），搬成可上桌的角色只能手動複製貼上。
拍板：自動偵測不做——條目是自由文字，角色與物種設定機器難分（卡 2 的 Rigurd 是角色、Wolf 是物種），改 AI 判則燒玩家額度（不替玩家花錢原則）。判斷交給玩家手動點擊，程式零猜測。
要做：
- 世界書條目加「轉成角色卡」：標題→卡名、內文→簡介，建卡成功後原條目刪除——內容 1:1 進卡，零遺失。`{{USER}}` 型玩家人設條目同按鈕即可轉成玩家卡。
- 角色卡加「轉成世界書條目」：各欄位（含私有筆記）合併成一條常駐條目，標題＝卡名，預設 GM 可見（同匯入慣例）；使用中的卡（已在桌上）擋下並提示，未使用才轉、轉後原卡刪除。用途：用不到獨立 AI 的路人降級回設定集。
- 按鈕位置照全域原則：編輯畫面動作鈕置頂（標題正下方）。
- 字串 ×10 語系。
驗收：卡 2 的 Rigurd 條目一鍵轉卡、內容無損；未使用卡反向轉回條目；使用中的卡被擋並提示；cargo test 蓋雙向轉換（含內容完整性）。

## 第六項：開場白選擇＋起始狀態匯入（中；2026-08-03 拍板並實作完成）
現況：匯入帶開場白的卡會問一句，答好就把 `first_mes` 貼成 GM 開場旁白（三個入口都問）。實測「兽人的洞穴」暴露兩個缺口——
- 它的 `first_mes` 是**說明書**（列出「開場白 2＝第 1 天初始模式／開場白 3＝第 120 天沦陷模式／開場白 4＝英文版」與劇透提醒），真正的劇情開場在 3 條 alternate_greetings 裡。照現行邏輯貼出去等於貼使用手冊。
- 備用開場白 1 結尾自帶 `<details><summary>状态栏</summary>`＋「沦陷天数：第 1 天」——**開場白就是起始狀態的來源**，貼進對話時沒解析，狀態欄拿不到初始值、玩家還會看到裸露的 details 區塊。
要做：
- 選擇：`card_opening` 改回傳全部開場白（first_mes＋alternate_greetings，巨集皆已替換），前端把現在的是非 confirm 換成自製選擇面板（比照 AI 生圖面板寫法，原生 dialog 只有兩顆鈕）——一條一列顯示前兩行預覽，點列展開全文（全文自帶卷軸，一次只展開一條），展開後另一顆「貼出這條」才真的貼；不挑就關掉。
- 只在世界書路徑問（世界書面板匯入、角色卡改道匯成世界書）：匯成角色卡＝這張卡是要上桌的角色，開場白已在卡上，不再由 GM 貼一次（2026-08-03 拍板）。
- 狀態：貼開場白走與 GM 旁白同一條解析——`transport::extract_state_block` 剝除狀態區塊、欄位併進 `TableState`，事件帶當回合快照寫入 transcript（守住「目前值＝最後一則事件快照」不變式，實作宜由後端單一指令完成，別讓前端各寫一半）。
- 字串 ×10 語系。
不做：英文版開場白要求的「打開世界書 Rigurd (EN VER.)、關掉 Rigurd」條目開關——條目啟停留給玩家自己點，程式不猜。
驗收：兽人的洞穴走世界書改道後可從 4 條開場白展開挑「第 1 天」那條；貼出後對話看不到 `<details>` 區塊、狀態欄顯示「沦陷天数：第 1 天」；沒有備用開場白的卡只列一條；不挑就什麼都不貼；照樣匯成角色卡則完全不跳面板。cargo test 蓋開場白清單與狀態剝除。
