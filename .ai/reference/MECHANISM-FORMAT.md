# 機制格式規範（v1）

狀態欄的資料標準：一棵**狀態樹**（值）＋一份**機制**（規則）。ST 各家協定匯入時被翻譯成它，
本 app 自己的模板也直接用它寫。判斷邏輯一律資料驅動——程式讀規則決定怎麼收更新，不寫死欄位名。

翻譯判準一條：卡片有硬標記（`<status…>`、`<UpdateVariable>`、`[initvar]` 這類）就走本地解析；
沒硬標記的長尾留給「AI 卡重構」按鈕，產物一律人審。

## 狀態樹

葉子存值（字串）、分支存子節點，深度不限。序列化就是自然的 JSON：

```json
{ "World": { "Time": "清晨", "侵略度": "35" }, "亞瑟": { "好感": "40", "HP": "480/500" } }
```

- 存在每則對話事件的快照裡（`transcript/<scene>.jsonl` 的 `state.tree`），收回上一句＝整棵樹回到那一刻。
- 桌上的目前值是最後一則事件的快照（`state.json` 的 `state.tree`），兩者恆等。
- 路徑寫法：點分字串 `World.侵略度`。欄位名本身含 `.` 者對不上規則，對不上就是沒規則、走預設行為。

## 機制

存在 `state.json` 的 `mechanism`，**不進逐則快照**——規則是這桌的設定，不隨對話變動。

```json
{
  "version": 1,
  "incremental": true,
  "rules": { "亞瑟.HP": { "kind": "pair", "min": 0, "update": "delta", "inject": "turn", "branch": "亞瑟" } }
}
```

- `incremental`：這桌是否走增量協定——數值由本地記帳，模型只回報這一幕變動多少（見下「統一協定聲明」）。
  匯入到 `[initvar]` 或 `[mvu_update]` 任一標記就設成 `true`；一般全量快照型卡片維持 `false`，狀態照舊每輪全量注入。

### 欄位規則

| 欄位 | 意義 |
|---|---|
| `kind` | 型別，見下表 |
| `min`／`max` | 數值上下限，夾住模型給的更新；抽不到就不填、不夾 |
| `update` | 怎麼收更新：`delta`（只收增減量）／`replace`（照收新值）／`local`（app 自己算，模型唯讀）／`reject`（全拒） |
| `inject` | 何時進模型上下文：`turn`（動態數值，每輪回合尾）／`snapshot`（長文字欄，變動才送）／`rare`（純記錄，不送）。細節見下「注入策略」 |
| `branch` | 分支歸屬（樹的第一層節點名）。角色卡匯出只帶走自己那支 |

規則路徑可用萬用段 `*` 匹配任意同層 key，例如 `Heroes.*.好感` 比對所有英雄的好感欄。
比對優先序：精確路徑優先，沒有才找萬用段；多筆萬用規則命中時取萬用段數最少的那筆。

型別與預設值（建規則沒特別指定時就是這組）：

| `kind` | 說明 | 預設 `update` | 預設 `inject` |
|---|---|---|---|
| `number` | 純數字 | delta | turn |
| `pair` | 現值/上限對（`"500/500"`） | delta | turn |
| `roll` | 骰值欄，app 每回合本地重擲 | local | turn |
| `text` | 字串 | replace | snapshot |
| `list` | 清單／字典 | replace | turn |
| `counter` | 計數器，允許大跳（時間跳躍） | delta | turn |
| `read_only` | 唯讀 | reject | rare |
| `derived` | 衍生值：schema 預留，未實作 | reject | rare |

## 匯出匯入

角色卡（SillyTavern chara_card_v2）的 `extensions.table_tavern`：

```json
{ "version": 1, "rules": { "HP": { … } }, "initial": { "HP": "500/500" } }
```

`rules` 的 key 是**去掉分支前綴**的相對路徑，`initial` 是這張卡那一支的初始子樹。
匯入時補回 `<卡名>.` 前綴、`branch` 填卡名，初始子樹掛進 `state.tree.<卡名>`。
解析失敗一律略過、不擋匯入——一張卡壞掉不能害整批匯不進來。

### ST 的 `[initvar]`

MVU 型卡把整棵初始狀態樹寫成一條世界書條目：comment 以 `[initvar]` 開頭、**且該條目已停用**
（雙硬標記；comment 對了卻還啟用的是給模型看的說明文字，略過），內容是縮排 YAML 的巢狀字典。
角色卡與世界書兩條匯入路徑都會讀它，解析成初始樹補進 `state.tree`：

- **只補不覆蓋**——既有路徑一律保留，玩到一半重匯同一張卡不會把數值倒回初始。
- `{}` 保留成空分支（MVU 卡的道具、動態列表等容器，形狀要留著給後續更新填）。
- `{{user}}` 存字面，注入模型前才代換成這桌的玩家名。

### ST 的 `[mvu_update]`（欄位規則表）

MVU 型卡的規則表也是一條世界書條目：comment（或 title）以 `[mvu_update]` 開頭（不限停用，可能不只一條），
內容是縮排 YAML，每個欄位下面掛 `type`／`range`／`format`／`check` 等屬性。抽取判準：

- 只收路徑長度 ≥ 3 且最後一段是 `type`／`range`／`format` 的項目；同前綴但沒有這三個屬性的說明性條目
  （如 ST 卡常見的「变量输出格式」條目）自然被這條過濾擋掉，不必特判。
- 規則路徑＝去掉根節點與屬性名；路徑中任何一段是 `check` 就整條丟棄。
- ST 怪癖正規化（只在這一層做）：段落包住的引號剝掉；段落含 `.` 先拆成多段；`${a|b}` 展開成多條規則、
  `${x}` 換成萬用段 `*`；`HP/SP/MP` 這種同層併寫用 `/` 展開成多條規則。組合數超過 32 就整條放棄。
- 型別判定：`format` 值含「現值/上限」（含簡繁兩種寫法）→ `pair`；否則 `type: number` → `number`、
  `type: string` → `text`；規則路徑最後一段是 `roll` 開頭加數字（如 `Roll100`）且型別是 `number` → 改判 `roll`。
  完全推不出型別的路徑不建規則。
- `range` 以 `-` 拆成兩段、都 parse 得出數字才填 `min`／`max`（如「零阶-六阶」這種非數字區間就不填）。
- 同一條路徑的多個屬性（`type`＋`range`＋`format`）合併成同一條規則；同 key 以最新抽到的為準。

### 機制條目收編

被系統接管的機制條目不該再進提示詞——匯入時符合以下任一條件就把該條目設成停用（`disable: true`）：

1. comment 或 title trim 後（不分大小寫）以 `[initvar]` 開頭。
2. comment 或 title trim 後（不分大小寫）以 `[mvu_update]` 開頭。
3. content 含 `{{format_message_variable::`（ST 把整棵變數樹塞進提示詞的巨集，本 app 的樹走回合尾，
   不能讓它每輪重送一份）。
4. content 含 `<%`（EJS 腳本條目，改走觸發表；認不出來的也不送，見下「觸發表」）。

全量快照型卡片（狀態欄規則是散文、沒有這些標記）不受影響，條目照舊送模型。

## 統一協定聲明

`incremental` 為真的桌，GM 的 system prompt 末尾會附上一段固定協定聲明（zh／en 兩份，依語系挑選）：
數值一律用 `delta` 給增減量、現值/上限對只有上限改變才用 `replace`、文字欄用 `replace`／`insert`／
`remove`／`move`、骰值唯讀。模型只需要在回覆最後附一個 `<UpdateVariable><JSONPatch>…` 區塊；
本地依欄位規則決定收不收，被拒收的欄位會在下一輪的「上一輪被系統擋下的更新」區塊裡告知目前值
（`state.notes`，自癒回饋，跟著逐則快照走）。

## 注入策略

只在 `incremental` 的桌生效；全量快照型桌照舊每輪整棵樹全送（模型自己在跑那個機制，看不到全貌會漏報）。

**分支切割**：回合尾只送相關分支——桌級分支（World 之類沒綁角色的）＋玩家那支＋在場角色那支。
在場名單取平欄 `present`（模型每輪照報），比對到卡名就算在場（`亞瑟（受傷）` 這種註記照樣算）。
`present` 是空的就不裁——寧可多送，也不要因為模型漏報一欄就讓它整桌瞎掉。

**分支綁定**：角色卡對到樹的哪一支，先看面板指認（存 `state.json` 的 `branch_bindings`，角色卡 id → 路徑），
沒指認就全樹找 key 等於卡名的分支（廣度優先、深度上限 3、取最淺）。找不到＝這張卡沒有自己的分支，不裁不送。

**手足規則**：容器裡只要有一支綁到角色卡，同容器的其他分支就一律當人看，名字沒出現在在場名單一樣裁掉——
MVU 卡十幾個角色只會有幾張角色卡，剩下的沒卡也是人。只在容器不是樹根時生效：頂層放的是 World／Player
這類桌級分支，套下去會把整桌裁光。實測勇者卡（15 個英雄、在場 1 人）：回合尾 3,127 → 530 字元，換幕對齊 9,571 字元。

**三個注入等級的實際行為**：

| `inject` | 回合尾 | 換幕對齊 | 變動時 |
|---|---|---|---|
| `turn` | 每輪送現值，變動的加標記（`HP：420/500（-80）`） | 送 | — |
| `snapshot` | 不送 | 送 | 落一則 transcript 系統事件 |
| `rare` | 不送 | 不送 | — |

長文字欄的變動走 transcript 系統事件，不走回合尾動態塊：動態塊每輪重組、不留在歷史裡
（API 那條傳輸路下一輪就看不到），transcript 兩條路都會重播且吃快取。
凍結快照（system prompt）維持完全不含狀態文字——那裡動一個字，整條快取就滅了。

**換幕全樹對齊**：換幕後第一輪 GM 回合送整棵樹（排除 `rare`），標題明寫「以此為準」，
把模型的認知覆寫成本地帳。已對齊的場景號記在 `state.json` 的 `aligned_scene`，模型真的收到才記
（呼叫失敗就下一輪再送）。對齊不修正錯誤、只消除歧異——錯的值靠玩家在面板改。

**角色線**：角色只拿自己那支（含 `snapshot` 級、排除 `rare`），且放在機密段——角色線是全角色共用一條
session，放一般段會讓下一個被點的角色看到別人的數值。角色對狀態唯讀，不輸出狀態欄也不輸出更新區塊。

## 記帳落檔

每桌一份 `worlds/<world_id>/mechanism-log.jsonl`，每筆更新記帳落一行 JSON：
`ts`（本機時間）、`scene`（場景號）、`kind`、`path`、`detail`。`kind` 四種：

| `kind` | 意義 |
|---|---|
| `rejected` | 更新被拒收（唯讀、絕對值寫增量欄等），本地值不動，會進下一輪的自癒回饋 |
| `clamped` | 更新收下但被夾到上下限內 |
| `error` | 格式壞掉（路徑不存在、型別不符等），不算拒收，不進自癒回饋 |
| `absorbed` | 機制鷹架條目被接管、不再送模型（見上「機制條目收編」）；一次性事件觸發後釘旗標也記在這 |
| `skipped` | 卡片腳本認不出來、沒轉成觸發表，預設也不送模型（見下「固定型 EJS 的資料抽取」） |

寫檔失敗一律吞掉——記帳設施不該反過來中斷遊戲。

## 觸發表

存在 `state.json` 的 `mechanism.triggers`，一組觸發＝卡片裡一條腳本翻譯成的純資料。
每回合模型的更新套進樹**之後**求值，命中文本存進 `state.triggers`（跟著逐則快照走），
下一輪回合尾印出來。

```json
{
  "id": "亚瑟关系阶段",
  "title": "[Script]亚瑟关系阶段",
  "mode": "range",
  "scope": ["Heroes", "亚瑟·晨光"],
  "preamble": "[系統指令：以下當隱藏背景，不要複述]",
  "cases": [
    { "when": [ { "kind": "range", "path": "Heroes.亚瑟·晨光.Affection", "min": 180 },
                { "kind": "range", "path": "Heroes.亚瑟·晨光.Desire", "min": 90 } ],
      "text": "當前關係：聖誓伴侶…" },
    { "when": [], "text": "當前關係：觀察對象…" }
  ]
}
```

- `cases` **依序求值、第一個命中就停**，空 `when` 的那筆是兜底（來源腳本 if／else-if 鏈的語意，
  巢狀鏈攤平成一層：每筆 `when` 帶上所有祖先條件）。
- `mode`：`range` 條件成立就持續注入（關係階段、環境氛圍）；`once` 命中後把 `flag` 路徑釘成 `true`，
  下一輪條件自然不成立——事件演過就是演過，模型翻不了案。旗標路徑同時自動建一條 `read_only` 規則。
- `scope`：這組觸發看哪一支分支。該支被回合尾裁掉（角色不在場）就不注入；空＝桌級，永遠注入。
- 文本裡的 `{{state:World.Invasion}}` 佔位在注入前換成樹上現值（來源腳本的 `<%= 變數 %>`）。

### 條件三型

| `kind` | 欄位 | 成立條件 |
|---|---|---|
| `range` | `path`、`min`／`max`、`min_exclusive`／`max_exclusive`、`default` | 現值落在區間內。`"480/500"` 取現值；葉子不存在時用 `default`，沒填就不成立 |
| `contains` | `path`、`any` | 字串含 `any` 任一項 |
| `flag` | `path`、`expect` | 葉子是 `true`／`1` 算真，其餘（含不存在）算假 |

同一筆 `when` 裡的條件是 AND。拍板的第四種條件「計數器門檻」與數值區間判斷邏輯逐字相同
（差別只在欄位型別），共用 `range` 不另立型別。

### 固定型 EJS 的資料抽取（解析≠執行）

MVU 卡把上述機制寫成 EJS 腳本條目。匯入時辨識「`getvar` 讀變數＋數值／字串／旗標比較＋
各分支一段文本」這種固定型，轉成觸發表；**腳本從不執行**，也不引入樣板引擎。認不出的整條跳過
並記一筆 `skipped`。認得出與認不出的 EJS 條目一律停用（不進提示詞）——原生 ST 是外掛執行腳本、
模型本來就看不到原文。

回 `None`（辨識不出）的形狀：擲隨機數（`_.random`）、跑迴圈統計、字串切割算百分比（衍生值，
拍板 2 預留不實作）、讀整個分支物件、沒有 `getvar` 變數來源、`<%= %>` 裡是運算式、所有分支都沒文本。
勇者卡 30 條 EJS 的實測結果：21 條轉成觸發表（13 條角色關係階段、4 條環境氛圍、4 條國家事件），
9 條進帳本。
