# 卡片重構規格（ai-card-refactor）

任務背景與拍板見 [ai-card-refactor](../handoffs/ai-card-refactor.md)，機制格式見 [MECHANISM-FORMAT.md](MECHANISM-FORMAT.md)。
本檔是分包實作規格，逐包討論定案後寫入。

## 總則

- 入口兩處：匯入完問一次＋世界書分頁常駐按鈕，旗標防重複問。任何卡都能按（不以帳本非空為條件）。
- 一顆按鈕一次產三類產物：**角色**（人物合集條目切成角色卡）、**介面**（散文介面指令抽成狀態樹）、**機制**（殘渣抽成欄位規則＋觸發表）。
- 玩家面雙軌：一鍵全部套用；展開後逐項勾選（預設全勾），兩條路通向同一顆套用鍵。
- 產物一律人審後才落檔（紅線）；套用無還原，自動落檔 `refactor-outcome.json` 並可匯出，不滿意就重按重構覆蓋——已重構過的桌會先警告重花額度並覆蓋。倒退只留「匯入重構卡」一途。
- 卡片內容永遠當資料、永不執行。抽不出的原樣留著，遊戲照常。

## 包 1：產物落地與人審面板

### 結果卡

```
整理好了
拆出 15 個角色 ・ 遊戲介面搬進 app ・ 收編 3 條規則
〔全部套用〕 〔展開細看〕 〔不要〕
```

只有真的有產物的區才計數；某區解析失敗就不出現在結果卡上（玩家零感知，該區原樣不動）。

### 展開細看

四區，每項一個勾選框、**預設全勾**，底下同一顆〔套用〕；每列可展開看全文，出處灰字獨立一行，方便核對 AI 有沒有切錯：

- **角色**：逐人一行（合集條目切出的七人＝七行）。
- **世界書條目**：整本重寫產出的新 setting／mechanism 條目，逐條勾選。
- **介面**：一項，勾＝搬進 app 本地渲染，不勾＝維持模型每輪自輸出。
- **機制**：僅匯入舊卡出現，逐條。

展開層只做「要／不要」。改名、調公私設定不在此做——套用後走既有角色編輯畫面，審核面板不重造編輯器。

### 部分套用

**沒勾的一律不動**。取消勾的角色留在原世界書條目裡，該條只搬走勾中的人（例：七國守護者只轉兩人，剩五人段落原樣留給 GM 當背景）。

### 落檔與倒退

| 產物 | 落到哪 |
|---|---|
| 角色 | `characters/` 多出 N 張 |
| 介面 | `state.json` 狀態樹整份重建為新欄位集（同名鍵沿用現值） |
| 機制 | `state.json` 的 `mechanism.rules`／`triggers` |

來源條目：整條刪除，且僅當引用它的全部產物都被套用；有任何一個沒勾就整條保留。

套用無還原（見總則）；不滿意就重按重構覆蓋。

產物契約沿用一句話開桌的 `{parsed, raw}` 雙軌：解析失敗退成原文，不整包爆掉。

### 驗收（零額度，AI 未接）

手寫假產物 JSON 餵進面板：全勾套用→查檔案→倒退→回原樣；再跑只勾兩角色，確認來源條目剩五人、角色卡只多兩張。

## 包 2：AI 呼叫與提示詞

### 四階段

| 階段 | 送什麼 | 回什麼 | 次數 |
|---|---|---|---|
| 盤點 | 整張卡 | PERSONS（哪些條目是人物，各切出誰）＋INTERFACE（含 playable 判定）＋PLAN（新世界書結構規劃） | 1 |
| 人物展開 | 同一份脈絡＋這個人 | 該人的角色卡產物 | 每人 1 次 |
| 條目重寫 | 同一份脈絡＋PLAN 這一條 | setting → CONTENT；mechanism → 可讀說明 CONTENT＋本地可執行 RULES/TRIGGERS | 每條 PLAN 條目 1 次 |
| 介面展開 | 同一份脈絡＋這條介面來源 | playable → `interface_shell` 產殼；其餘只抽 STATE | 每條介面來源 1 次 |

一次吐完會撞輸出上限也讓玩家空等；分次後每回輸出都只有一人或一條的量。欄位命名單一權威＝`known_fields`，逐呼叫累積已用欄位名再傳入下一次。

整張卡放 **system** 並標 `cache_control`（[transport.rs:1652](../../src-tauri/src/transport.rs) 既有機制），第二次呼叫起吃快取價——分次不等於脈絡送多次錢。

### 玩家看到什麼

進度列：`盤點中…` → `整理「七國守護者」 2/4` → 結果卡。中途可取消，**已完成的部分照樣進結果卡**（錢花了東西要拿得到）。

### 輸出格式

沿用一句話開桌的標記式文字（[genesis.rs](../../src-tauri/src/genesis.rs) `expand_messages`），不用 JSON——截斷時前面的產物仍可救回，且 `PUBLIC:`／`PRIVATE:` 直接對上角色卡欄位、解析器可重用：

```
## CHARACTER: <名字>
EMOJI: <一個 emoji>
PUBLIC:
<所有人看得到：外貌、身分、公開性格>
PRIVATE:
<秘密、真實動機、內心話，只有扮演者看得到>
```

介面與機制另定標記，共用同一個解析器。

### 檔位與語言

- 檔位＝GM 同檔（`transport::gm_tier`），不另外問玩家。
- 語言＝**玩家的介面語言**（`transport::ui_language`）。拆卡順便翻譯：法文玩家拿到簡中卡，重構後整套產物是法文。
- 已知限制：只有被重構的部分會翻譯，沒動到的世界書條目維持原文語言（GM 讀得懂，玩家不直接看）。

## 包 3：人物切片落成角色卡

### 欄位對應

`名字→name`、`EMOJI→avatar`、`PUBLIC→public_md`、`PRIVATE→private_md`；顏色依既有 `PALETTE` 順序自動配（[App.tsx:4157](../../src/App.tsx)），檔位用預設，其餘留空。

### 來源條目怎麼拆

人物展開一人一呼叫，產出該人的 `## CHARACTER:` 區塊；不屬於任何個人的內容由盤點階段規劃進新 setting 條目（PLAN），條目重寫階段產出內容。套用時：

| 對象 | 去哪 |
|---|---|
| 勾中的人 | 角色卡 |
| 沒勾的人 | **各自一條獨立世界書條目，標記為人物**（吃包 4 的在場過濾） |
| 不屬於個人的內容 | 盤點規劃進新 setting 條目 |

來源條目本身照包 1 的刪除規則：引用它的產物全套用才整條刪除，有任何一個沒勾就整條保留。

沒勾的人切成獨立條目而非併回原條目：一人一條才過濾得動，併回去等於全員永遠常駐。

原條目與新條目的內容都是 AI 重寫的（順帶翻譯），不做原文起訖定位——那容易切歪。

`WorldbookEntry` 需新增人物標記欄位（`#[serde(default)]` 相容舊檔）。

### 收據要補一塊

AI 直接套用無收據（見總則，無還原）。倒退只存在於「匯入重構卡」路徑——沿用既有匯入收據，但要新增存被取代來源條目的原文，倒退才插得回去（現有收據只記指紋、不記原文）。

### 常駐成本會降

西幻卡三條人物條目全是 `constant`，現況 1786 字元常駐（15 人擠在裡面，每人 119 字）。重構後常駐的只有勾中的角色卡＋一條總述，其餘各自成條、在場才進 context。玩家勾越少越省。

### 既有路徑留著

[worldbook_entry_to_character](../../src-tauri/src/data.rs) 處理「一條＝一人」、不花錢；重構按鈕處理「一條＝多人」、要花錢。兩條並存。

### 沒有立繪

拆出的角色卡無圖、卡片較矮（既有設計）。想要圖走生圖功能，重構不自動花那筆錢。

## 包 4：在場過濾與角色自動上下場

### 現況

[state_scope](../../src-tauri/src/transport.rs) 的在場過濾只管**狀態樹分支**（含手足規則）。世界書條目沒有任何過濾，constant 一律全文進 system；角色卡也一律進 system，封存的才不進（`load_active_cards`）。

### 核心限制：不能在幕中動 system

system 是快取前綴，幕中改動＝快取全失效（prompt-cache 的 85–88% 命中歸零）。所以幕中一律只能往歷史尾巴 append，真正的增減留到換幕（快照本來就重建，零額外成本）。

### 人物條目

| 放哪 | 內容 |
|---|---|
| system 凍結快照 | 只有一行名冊：「這桌還有這些人：亞歷山大、泰蘭德里爾…」 |
| 歷史 | 某人**首次在場**時 append 全文，當一則系統事件 |

離場不拔。換幕重置歷史，登場記錄跟著清空、重新算。**進場付一次全文，之後吃快取價。**

### 角色卡自動上下場

- **幕中**：被帶出場 → 設定 append 進歷史（同上機制）＋ UI 立刻從隱藏區移到主區（側欄是本地狀態，不進 prompt）。離場不拔。
- **換幕**：這一刻才結算 `archived`——這幕沒出現過的收進隱藏區，出現過的回到角色卡區。

### 封存三態

`archived` 布林不夠用，要區分：

- **自動隱藏**：過濾造成的，可被劇情自動拉回。
- **手動封存**：玩家按的，永不自動拉回（玩家的決定不能被 AI 推翻）。

### 在場判斷

優先讀 `present` 欄位（模型每輪報）。重構落卡時順便建**最小狀態欄含 `present`**，並讓狀態列顯示出來（玩家看得到「在場：亞歷山大、卡西安」）。沒有 present 時退回正文人名比對——會誤判（「亞歷山大的傳說」也算出場），代價只是多送一份設定、換幕即修正，不為它加複雜度。

### 玩家看到什麼

角色隨劇情自動上下場，省錢機制在底下跑。除此之外無新 UI。

## 包 5：介面規則本地化

### 現況（西幻卡）

`回复规则` 要求模型每輪輸出完整 `GoldenRPG_UI` 五模組：CurrentView（5000–15000 字劇情＋時間地點＋物品技能＋3 行動）、WorldSystem（**11×7 = 77 格矩陣**＋座標）、LocalSystem（區域描述＋6 地點×各 3 動作）、GuildBoard（4 傳聞＋任務板＋積分）、CharSheet（基本＋裝備＋筆記＋劇情軸＋奴隸清單）。每輪估 8000–20000 token。

該桌 `world.md` 空、無角色卡、無介面殼——現在開起來玩，這包 XML 沒有東西能渲染，玩家看到滿螢幕標籤。

### 分類處置

| 類別 | 內容 | 處置 |
|---|---|---|
| 創作 | 正文、推薦行動、傳聞 | 留給模型每輪產 |
| 固定 | 11×7 矩陣、地點座標表 | 存一次進狀態樹，**永不重送**（卡片自己寫「禁止有任何修改」，每輪重畫 77 格是純浪費） |
| 慢變 | 時間、地點、座標、物品、技能、任務、裝備、劇情軸、角色表 | 進狀態樹，只報變動 |

模型輸出從「整包 XML」變成「正文＋幾行變動補丁」，走既有增量協定。

### 渲染三層

1. **卡片自帶 HTML 殼** → 走 [interface-card-panel](../handoffs/interface-card-panel.md) 既有沙盒路徑，直接用。
2. **盤點判定「玩家可完全在裡面遊玩（含對話歷史）」的介面** → 走 `interface_shell` 產殼，塞進同一個沙盒；只有狀態數據的介面不產殼，直接走第 3 層保底。
3. **保底** → app 通用元件（格子地圖、標籤清單、按鈕列、資料表）把狀態樹的值列出來。

資料一律以**狀態樹為權威**，渲染層壞掉不影響數值。

### 渲染失敗怎麼辦

顯示說明：這次介面畫不出來，換個聰明點的模型重新重構通常會好。**不強制**——玩家可以就用保底畫面繼續玩。（AI 產的 HTML 會錯，但模型每輪自吐的 XML 一樣會錯，差別只在錯一次還是每輪錯。）

## 包 6：機制殘渣抽成規則與觸發表

地基齊備（格式規範＋執行期都在 state-values-mvu 做完），這包只是讓 AI 產出符合既有格式的東西。

- **產物**：欄位規則（型別、上下限、誰能改）與觸發表（數值區間 → 對應文本）。
- **來源**：帳本的 `skipped` 條目（有 `<%` 但認不出的 EJS），以及完全沒硬標記的散文機制條目——後者是大宗，例如迷宮之主的 `战力与威胁系统` 用散文寫了七階威脅度分級，正好是觸發表的形狀。
- **套用後**：機制重寫成一條鎖定唯讀（locked）世界書條目——說明文列在世界書給玩家與模型看，RULES/TRIGGERS 由 app 本地執行；來源條目照包 1 的刪除規則處理，不再有停用墓地。
- **防劇透**：只管遊玩畫面（狀態欄／殼不主動列未觸發事件），世界書內容不因此刪減。
- 公式型機制移交包 7。

## 包 7：算術求值器（derived／Roll 共用）

`derived`（衍生值）在規範裡是 schema 預留未實作，導致公式型散文機制抽不動（例：迷宮之主 `小队刷新机制` 的「每層 3 支＋名聲每高一階 2 支＋威脅高時低階減半」）。

- **規模**：tokenize＋遞迴下降 parse＋eval，加 `min`／`max`／`floor`／條件約 250 行加測試（對照：[ejs.rs](../../src-tauri/src/ejs.rs) 820 行）。
- **安全**：自寫求值器不是 `eval`，只認數字與自家欄位路徑，卡片永不執行的紅線不受影響。
- **一做三用**：`derived`、既有的 `FieldKind::Roll`（骰值本地擲）、[ttrpg-rules-system](../tasks/ttrpg-rules-system.md) 的骰池與傷害公式共用同一個求值器。
- **已知風險**：難點在散文歧義（「威脅度較高」是多高，AI 得自定閾值）。但公式是人審產物、可倒退，且錯得一致——改一次全部修正，比模型每輪心算出不同答案好抓。
- **排序**：前六包之後，不阻塞任何一包，要插隊也可以。
