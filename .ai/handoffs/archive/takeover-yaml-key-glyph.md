# takeover-yaml-key-glyph — 接管桌續聊 GM 把清單欄 YAML 鍵寫成繁體

## Summary
接管桌續聊時，GM 把清單欄（如「在場人物」整串 YAML）裡的鍵寫成繁體（行動／裝備／體力），原卡腳本只認簡體鍵（`fields = ['身份','行动','装备','体力','心情','内心']`），人物卡片少欄。出處：[ai-card-refactor](ai-card-refactor.md) B5。

## 現況（2026-10-27）
- 重現（測試通道，Haiku 5.5，NorthHall-structure.png＋TestCards/NorthHall-structure-statusbar-outcome-v2.json 匯入重構卡全部套用）：8 回合中 1 回合漂移——賀錚一人的 `行动` 寫成 `行動`，介面他的卡片少 📝 那行；下一回合自己回正。測試 root：`scratchpad/glyph/root`（已退回到漂移狀態，留作 fixture）。
- 根因：清單欄的值是一整串字串（`json_to_node` → Leaf），`canonical_path` 的字形折疊只管路徑段，值裡的鍵沒人校正。系統提示語言規範「禁止簡體字」把模型往繁體推；接管指示已有「路徑與值裡的鍵名照目前狀態裡的原字逐字抄」（7ab0b220），仍會漏，且錨在「目前狀態」，漂移後會被當成原字。
- 同類缺口：物件值 replace 的巢狀鍵（`json_to_node` 的 Object 分支）也不折。

## 做法（三方共識 2026-10-27：做法 B，提示詞不動；物件值巢狀鍵與結構化成樹路徑由主線另立案）
寫入時把清單欄值裡只差字形的 YAML 鍵改回原卡寫法：`src-tauri/src/mechanism/list_keys/`（`scan.rs` 鍵定位、`mod.rs` 參考與校正），掛在 `mechanism/apply.rs` 每筆 patch 對回路徑之後。
- 範圍：明確規則（精確或萬用）判為 List 的欄位，replace／insert 的字串值；一般文字欄、物件、依現值推定的欄位不動。
- 鍵定位支援子集：半形空白縮排；`鍵: 值`、`鍵:`（接更深一層）、`- 鍵: 值`、`- "純量"`、`- 純量`；鍵是普通純量、鍵尾只認半形 `:`；值可空、普通純量、同行收尾的雙引號（跳過引號內）、`|`／`>` 區塊純量（底下縮排行全當值）。tab 縮排、單引號、flow、跨行引號、引號鍵、錨點／別名／標籤、文件分隔線、縮排對不上、多行普通純量一律整份保留原文。只換鍵那幾個字，冒號與值逐位元不動。
- 參考鍵按欄位、按結構位置（父鍵路徑與序列項目，父鍵也折疊比對；同折疊的鍵在別的分支互不影響）：refactor-outcome 該欄初始值（載入層 `resolve_list_key_seeds` 填進不落檔的 `Mechanism.list_key_seeds`）→ guide 該欄範本（行首 `- 欄位：` 底下像 YAML 的行，只補前者沒有的折疊類；條目名稱完整路徑優先，只比末段時要末段在這桌只對到一個欄位；綁不到或多份不同就不用）→ 整批開始前的目前值。初始值與目前值只收出現兩次以上的鍵（一次的可能是人名）；同一層同一折疊類兩種寫法整類移出。精確相符優先、折疊唯一才改、同一映射改名會撞重複鍵不改。
- 留痕：寫入成功才記一筆 Ignored（欄位、行號、舊鍵→新鍵、依據），不回饋模型。
- 前端只有世界書帳本面板讀記錄種類，Ignored 不列，玩家看不到校正記錄。
- 已知限制：只有一位人物的初始值、又沒有 guide 範本時，參考只能靠之後目前值累積到兩位以上。zod 桌與接管桌互斥（`mvu_engine/wiring.rs` 的 zod 判定遇到已重構的桌回 None），本案只涵蓋 `apply_updates_typed` 路徑。
