# Task
Task-ID: room-story-area-fix
Title: 桌面版房間畫面故事區被擠到 0 高，held 時看不到重生／收回鈕
Status: done
案別：小案（只改 `src/styles/room.css`，核心約 10 行）

## 問題
桌面版房主的房間畫面在一般視窗高度下，故事區被擠到 0 高；GM 卡住（held）時「重生上一回合」「收回上一回合」也看不到。

## 根因（測試通道量測，800×600 視窗，內容高 568）
- 不只是資訊列：資訊列（158）＋回合列（86）＋頁籤（47）＋房主鈕列（53）＋輸入區（206）加總 550，已超過房間畫面的 492。
- 整條欄裡只有 `.story` 是可縮項（`flex: 1; min-height: 0`），所以它承擔全部不足，剩 24（只剩 padding）。
- `.app.party-embedded` 內容溢出卻不能捲（主欄 `overflow: hidden` 裁掉），手機版那條 `position: sticky` 的輸入區又疊在房主鈕列上，鈕列整列被蓋住。

## 修法
- `.desktop-room` 放不下時整個房間畫面一起捲（`overflow-y: auto`）。
- `.app.party-embedded` 不縮（`flex: 1 0 auto`），故事區基準 10rem（`flex: 1 0 10rem`）：有空間就長高，故事長了在自己框裡捲。
- 嵌在桌面版時輸入區取消 sticky。手機版（`party/src/App.css`）不動。

## 範圍
只讓故事區看得到、捲得動、鈕看得到；資訊列收合、按鈕搬家等完整版面整理屬 room-desktop-layout。不動 `DesktopRoom.tsx`（room-seat-delegate 會碰）。

## 已知限制
- 視窗矮（800×600）時外層要捲一下才看得到輸入區，故事區本身也會捲（雙層捲動）；收掉資訊列等空間留給 room-desktop-layout。

## 交給後續（room-desktop-layout）
- 資訊列開房後預設收合，只留房號、狀態、邀請連結、關房一列；生圖開關與最近錯誤收進去，或只在有錯誤時展開。
- 回合列的錯誤句與資訊列「最近錯誤」重複，只留一處。
- held 時重試與換模型鈕搬到回合列，跟「跳過這段，繼續」並排。
- 矮視窗時只讓故事區長高，回到單層捲動。

## 驗收
verify 16 步綠；測試通道 800×600 與 1280×716 held 截圖（故事內容、重生／收回鈕都看得到）。
