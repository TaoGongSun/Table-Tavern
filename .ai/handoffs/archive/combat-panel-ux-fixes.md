# combat-panel-ux-fixes

Status: done（2026-11-14 合 main）
案別：小案（立案估核心 100–200 行，實作約 +83 −21、測試約 39）。
來源：待實測清單補驗（vq3／A 批，第 24、33、34 項）主線親看截圖後認定的六個玩家會遇到的問題。

## 範圍
1. 戰鬥面板 HP 旁有 ⚠／灰字時值被擠成直排：標記換行，值維持橫排。
2. 玩家手改 HP 成非「現值/上限」：手改當下擋下並提示；GM 被拒的標記改說「HP 要寫成現值/上限」，不怪 GM。
3. 敵人被移除後它的 ⚠ 還留在行動順序下：一併不顯示。
4. 骰值寫錯的警告只在收合的骰池裡：收合列顯示 ⚠ 與筆數。
5. 收回／復原上一句後左欄「隱藏角色」沒同步：收回、復原後重讀本幕出場集合。
6. 正當的抗性減半被依骰面蓋成全額：改提示詞讓 GM 照既有規則不帶 dice（A 案）。

## 現況
- 1–6 已改（分支上，未合 main）：
  1. `combat.css`：值列含拒收標記／依骰面灰字時換行，標記獨占下一行。
  2. 前端 `isHpPath`／`isHpText`（`state-format.ts`，同後端 `Hp::parse`）：HP 格手改不合格式不存、輸入框留著、下方紅字提示格式；後端非法現值的拒收帶 `bad_current`，標記改講「HP 要寫成現值/上限」。推翻 `plans/ttrpg-combat-tracker.md` §2「手改照舊放行任何值」（該條原本未裁決，主線同意推翻）。
  3. `CombatSection` 散列拒收：敵人已不在時，它子欄的標記不列（`missing` 照列）。
  4. `DicePoolView` 收合列顯示 `⚠ N`（N＝展開後 ⚠ 行數），房間手機共用。
  5. 角色 controller 加 `reloadAppearances`（整份重讀 `scene_appearances`），收回／復原成功後呼叫。
- 6 走 A 案（主線定）：戰鬥指引（`panel_prompt.rs::combat_guide` 中英）與依骰面改套的回饋句改成「抗性、減半時 value 只報調整後的量、不帶 dice，旁白照樣標骰號」；「以骰面為準」裁決不動。
